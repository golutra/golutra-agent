# 以对照实验筛选运行时优化

日期：2026-09-19。保留本轮之前的工作区修改；不提交、推送或发布。基线为上一轮验收的 0.3.1 release 二进制，SHA-256：`d804d929424e1162e149c39d58bd1c321682776c0b4309786d65ee82319e52df`。

## 采用标准

每个候选先通过对应的正确性回归，再用冻结二进制进行真实上游对照。只有可复现的正确性收益或不降质的性能收益才进入最终实现。失败、中止和无效实验必须记录。测试通过不等于已证明普遍提速；专项恢复能力不等于通用编码能力。

使用同一网关 Responses、gpt-5.6-sol、medium、相同权限、独立 workspace/home，交替候选顺序。编译不与本轮性能对照同时运行。运行平台仅 macOS arm64。

## 实验与发现

### A：把实际验证失败送回模型

旧实现只向模型提供失败断言与通用纠偏要求。新增真实 `cmp` 验收回归在旧代码下失败：模型没有收到命令和 `differ` 输出。候选在纠偏时按 evidence ID 关联尚未通过的检查，追加有界、脱敏的命令、目录、退出码、输出片段与 artifact 引用。不改变验收判定或成功条件；不将已经恢复的失败再次作为阻塞。

新增上下文最多四项，诊断 JSON 总计最多 6144 字节，仅在需要纠偏时生成。没有可关联的失败时，提示与旧实现一致。相关测试覆盖已恢复检查、重复证据、无关联证据、Unicode/转义后的真实大小和秘密脱敏。

`scripts/compare_optimization_variants.py` 包含两个合成反馈专项，以及解析器修复和多文件金额计算重构。反馈专项将外部部署/导入限制放在验证器诊断中，刻意检验反馈链路，不能用于声称普通任务成功率提高相同比例。普通任务的已有测试文件由摘要保护，交付还经过独立行为判题；进程退出、运行时终态和产物判题同时通过才计为严格成功。

首轮反馈专项：旧版 0/2，反馈候选 2/2。部署任务从失败变为完成，但候选发生了 16 次请求；追踪发现双引号变量未展开，以及代码变更后需要重跑的历史检查。保留这些额外成本，不把提前失败的旧版与成功新版直接比较速度。

首轮四项全部结束：基线严格完成 0/4（独立产物判题 3/4），反馈候选严格完成及产物判题均为 4/4。总耗时包含失败为 380.3 s / 204.0 s，请求数 67 / 46。解析器基线产物正确，但在不具体的反馈下继续修改/检查，最终 145.5 s 截止；候选 54.6 s 完成。该任务集刻意覆盖失败恢复，不能据此推断一般任务的旧版成功率为零，或宣称总体性能稳定提升 46%。

### B：实跑暴露的 shell 语义问题

模型发出 `--workspace "$PWD"`，执行器却将 `$PWD` 原样作为目录，产生文件不存在错误。原因是 shell 元字符判断忽略了双引号内的变量/命令替换。不受限模式下应该使用既有的非 login shell 路径进行展开；受保护模式仍要求显式脚本，不新增隐式授权。单引号与转义后的美元符号应保持字面值。

### C：长日志纠偏

第一版反馈复用既有的头部预览；构造长验证日志时，末尾断言可能缺失。候选需要从当前报告关联的已保留 artifact 中提取有界首尾片段，再脱敏投影；完整日志与原始验收事实不变。

B/C 均先增加回归并观察旧实现失败，再修复。清除本地测试进程的代理变量后，policy 34、runtime 231、tools 187 项通过，runtime 一项忽略；初次 runtime 的两个 loopback 恢复测试遇到代理 502，保留该失败记录，没有改动恢复策略来绕过测试。

### D：只改变进展提示的频率

以包含 A/B/C 的 `robust` 冻结二进制为对照，将系统提示最后一句从每批工具前说明改为发现或计划变化时简短汇报，得到 `milestones`。其余提示和生产代码一致。交替运行同一组四任务；首轮只用于筛选，如出现质量下降或未看到明确收益则回退。若有收益，必须再次配对确认才采用，不能按一次随机速度或提示字数决定。

筛选中部署任务两端同为 9 次请求、约 39 s；CSV 两端均出现产物正确但运行时未完成。已经恢复原提示，不采用频率修改。两个版本都复现的失败不能归因于某一句提示词：轨迹显示旧的 LF 临时诊断与后来独立验证器要求的 CRLF 冲突。

### E：独立验收下过期探索义务的冲突

旧逻辑仅允许 BestEffort 合同解除过期探索诊断；配置外部验证器后转为 Independent，即使当前产物通过外部检查，早期成功的临时断言仍被要求永久复验。模型于是反复切换旧假设与新要求。

新增无模型随机性的真实工具序列：写 LF → 成功断言 LF → 改为 CRLF → 独立 cmp 通过。目标是仅在 Open、无显式 completion criteria、当前独立验收通过时，解除过期的成功 Diagnostic 义务。失败诊断、正式测试、Strict、显式条件、过期或缺失的独立验收仍保留。原始探索事实继续可观测。

E 的真实工具序列回归通过；边界测试最初错误使用 `assert 1 == 1`，该常量表达式按已有规则不是运行状态验证。替换为真实文件存在断言后，正负向边界均通过，没有放松诊断识别器。

### F：测试生成缓存造成验证循环

D 最终结果：robust 严格完成 2/4，milestones 3/4，两者独立产物判题均 4/4。multi_file 的 robust 耗时 145.5 s 后截止。完整轨迹表明代码修改后依次执行两个 unittest，第二个创建 `__pycache__/test_decimal_regression.cpython-314.pyc`，导致第一项测试被判过期；重复组合命令又有不同身份，未解除原义务。

新增回归先失败，修复后通过：仅在工具成功、运行时认定正式测试通过、副作用清单完整、变动全为 `__pycache__` 下的 `.pyc` 时，这批缓存变动不使先前验证过期。原始变动与输出继续记录，不全局忽略目录，也不改变 Python 环境。直接编辑、失败测试、未知副作用、独立 `.pyc` 或混入源文件变动仍使验证过期。此规则是测试产物的新鲜度处理，不是对执行任意恶意测试的安全隔离保证。

E/F 后 runtime 234 项通过、1 项忽略；policy 34 与 tools 188 项通过。提示频率实验保持回退，后续优先复测已经复现的正确性修复。

补充非配对回归：最终 verified 的解析器任务两次均通过（29.6 / 21.4 s），部署反馈两次均通过（42.6 / 32.0 s）。加上配对中的 CSV 与 multi_file，最终版本四类任务各两次，严格成功及独立产物判题共 8/8，受保护测试文件均未改变。这四次补跑没有同期旧版对照，不能单独计算提速。

## 不采用的方向与依据

上一轮最终实跑归档中的 19 个工具就绪至响应结束样本累计 1036 ms，中位数 8 ms，最大值 455 ms。这个已记录的等待相对 243.5 秒任务总耗时很小，不足以支持引入提前派发及其断流重放复杂度。缺失样本没有补零，这也不是未来所有任务的性能上限。

已有追加式上下文、压缩、恢复和原始结果保存机制继续保留。本轮没有因为论文报告了收益就增加递归模型调用、Code mode、额外后台服务或监督模型。
