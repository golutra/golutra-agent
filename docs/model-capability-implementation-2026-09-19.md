# 模型能力架构实施与验收

日期：2026-09-19。对应[分阶段方案](model-capability-architecture-plan-2026-09-19.md)。本轮保留原有工作区修改，不提交、不推送、不发布；当前版本仍为 0.3.1。

后续按真实失败轨迹筛选的纠偏反馈、shell 展开和验证循环修复，见[迭代实验记录](optimization-experiments-2026-09-19.md)。下面的结果属于本阶段冻结版本，不与后续版本混算。

## 变更

| 阶段 | 实现 | 边界 |
| --- | --- | --- |
| 0 | release 基线；保存每行到达时间；分别记录任务终态、进程退出和终态导出时间 | 统一宿主单调时钟；缺失时间为 null；失败样本保留 |
| 1 | 工具注册表统一生成模型 shell 合同：仅 command；内部保留 argv；等待限幅；动作适用字段检查 | 命令冲突、硬超时、权限与进程归属仍严格校验；与动作无关的有界读取/等待提示、空占位通过 ignored_arguments 明示 |
| 1 | 隐式复合命令使用 bash -c；小预算为进程重读预留正文空间 | 保持 PATH/工具链一致，显式 -lc 不变；避免诊断字段挤占正文导致游标不前进 |
| 1 | 检查点持久化使用专用错误入口 | checkpoint.py 不再触发检查点恢复建议；模糊/歧义补丁仍拒绝 |
| 2 | 实施并独立测试精简提示，最终恢复原系统提示 | 精简版本未达到稳定不降质的采用门槛；保留实验结果，不把字数减少作为提速证据 |
| 3 | 失败计数绑定策略和实际参数；确认工作区修改后允许重试 | 同样操作反复失败仍受门控；总预算、取消、未知效果和正式测试失败不绕过 |
| 3 | 验证成功检查后续行为文件修改，过期后要求复验 | 文档修改不使代码测试过期；已完成的阅读不升级成永久复读义务；没有依赖图时保守处理其他改动 |
| 4 | 增加只读 runtime_status；复用当前运行循环、进程监督器、子任务操作和持久投影 | 默认工具从 7 增为 8；不增加 slash 命令、后台服务或额外模型调用；子代理上限仍为 10 且可配置 |
| 5 | 普通 run bundle 耐久保存原始事实与观测；完整调试包显式生成 | 不延迟关键事实持久化；deferred 与 failed 区分；显式 export/refresh 保留完整审计 |
| 6 | 保留完整响应后派发；不启用 Code mode、提前派发或 WebSocket | 现有时序证据不足以支持增加这些复杂度 |

`runtime_status` 不接受会话或任务 ID。它返回当前执行的请求数、已知 token、耗时、最近 8 项未解决工具错误和验证；最多 8 个活跃进程、16 个子任务，明确截断。恢复后的累计历史继续保存在 trace，不伪装成当前执行计数。查询不消费进程输出或完成通知，不接管 lease，不暴露原始命令、请求或凭据。查询本身不算验证证据。子任务状态覆盖结果发布先于通知落盘的窗口。

## 使用

正常聊天、改代码和后台运行方式不变；模型可在有需要时调用 `runtime_status`。不用用户轮询。

```sh
cargo run -p golutra-agent-cli --locked --bin golutra-agent -- --yolo

# 普通交付：耐久状态与观测，完整调试导出延后
golutra-agent exec --run-dir /absolute/new-run '完成任务'

# 确实需要完整调试包时
golutra-agent exec --run-dir /absolute/new-run --full-run-export '完成任务'
golutra-agent --run-bundle /absolute/existing-run export /absolute/new-debug-export
```

## 实跑中发现并修复的回归

1. 动作级校验最初拒绝 `wait` 上的空 `input`、默认分页字段，以及 `list` 上的 `cursor=0` 等读取提示。模型会填写这些与当前动作无关的字段，造成独立产物正确但 runtime Partial。现在以统一动作规则处理有界读取/等待提示并返回 `ignored_arguments`，不逐个补默认值；真实 stdin、错误进程目标、类型和硬边界仍拒绝。
2. 验证新鲜度最初把任务中提到的文件阅读也视为代码断言。修改实现后，初次阅读被判过期，模型开始反复读文件、猜测隐藏需求和改代码，单个阶段达到约 596 秒。原提示对照同样暴露此问题；修复区分阅读事实和当前代码测试，增加真实“读取→写入→unittest”闭环回归，不要求重复阅读。正式测试失败与修改后复验仍有负向用例。
3. 一次对照超时后宿主拒绝进程组终止信号，旧基准脚本在保存 stdout 前抛异常。现在记录 cleanup 错误并保存已捕获输出，返回超时状态；不提权、不把缺失指标补成成功或零值。该次原始数据库与不完整报告保留，不计为完成的 A/B。
4. 成功的探索断言在后续编辑后也可能被升级成永久复验义务。Open 的尽力验收现在允许后续当前有效的正式测试或外部验收解除该派生义务；原始断言事实保留。Strict、显式验证、正式测试失败和效果未知仍不放宽。
5. 新增 `ignored_arguments` 使 1024 字节投影中完整 256 字节重读页无法放入，导致游标回退。为正文预留最小页空间，非必要元数据按已有优先级收缩；既有逐页重建全文测试复现并验证修复。
6. 实跑暴露隐式 `bash -lc` 重排 PATH：单命令使用 Python 3.14，复合命令却使用系统 3.9，`Path.write_text(newline=...)` 因此失败。隐式包装改为 `bash -c`，增加实际子进程环境验收；调用方显式使用 login shell 的行为不变。

已知失败的旧构建在修正版可用后停止继续消耗模型请求：对应实验明确标记手动中止，保留已完成阶段与中止证据，不纳入成功时延比较。精简提示试验中的模型也出现根据不明确反馈猜测隐藏要求的情况；当前采用保守回退，而非为该基准加入项目名或特定代码规则。
