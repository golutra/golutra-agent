# 持续长任务：默认不限，保留显式控制

本轮以 `9bbb87b` 为基线，参考本地 Codex `fc269b66` 的实现。目标是移除主机侧不必要的提前终止，保持模型、工具、验收和用户输入之间的连续循环。本文取代早期长任务文档中的默认次数和时间限制描述。

## 实现

| 路径 | 原行为 | 当前行为 |
| --- | --- | --- |
| 主任务总时间 | 默认 4 小时 | 默认无截止时间，显式预算仍生效 |
| 工具与失败次数 | 256 次工具、8 次连续失败，另有重复失败阻断 | 默认不限，真实错误送回模型；安全边界保留 |
| 纠偏 | Open 最多 8 轮，另有无进展截止 | 默认不限；进展提示不自动停止任务 |
| 输出续写 | 连续 8 次后失败 | 按正常结束语义继续，非法或不完整工具调用仍不执行 |
| 成本及 token | Governor 隐式总预算，子任务隐式累计输出额度 | 默认只统计；显式预算与单请求上下文容量独立生效 |
| 子代理时间 | 最长 30 分钟，包括截短显式长预算 | 默认不限；显式父任务预算向子任务分配并为父任务收尾预留时间 |
| 子代理数量 | 默认 10 并发 | 保持 10、可配置；完成后释放槽位，累计用量不阻断新子任务 |
| 过期探索诊断 | 部分合同只能由外部验收替代 | Open 中当前正式测试也可替代过期的成功诊断；显式条件、失败诊断与正式测试不豁免 |
| 多次压缩 | 旧用户要求主要依赖摘要保留 | 额外保留有来源的完整原始目标及最近补充，不依赖摘要复述 |

`GovernorLimits` 的标量零值统一表示未设限。`TaskContract.max_correction_rounds` 使用可选整数：省略或 `null` 表示不限，`0` 表示禁止纠偏，正数为明确上限。TypeScript、Python 类型及 JSON Schema 同步生成。

未设置任务预算时，主任务、恢复后的 steering、子代理执行和等待均不生成期限，也不把“无期限”转换为 1 毫秒。显式期限到期仍失败或取消，不伪报成功。取消信号、权限、运行中会话所有权、真实协议错误保持原有边界。

这里的“默认不限”指任务级累计限制。单次模型上下文/输出容量、工具输出大小和工具自身的执行超时仍按各自合同生效。例如后台 shell 默认一小时、可显式设置至 24 小时，见 [后台终端合同](background-terminals.md)；一个任务可以跨多次工具执行持续运行。

原文保留从可信 `objective` / `user_message` 来源中选择完整消息，先保留最早目标，再保留最近补充，按原始顺序放回。占用最多可用尾部预算的四分之一且不超过 2048 个估算 token；不会把截断指令当成完整要求，也不会把工具文本提升为用户要求。超出容量的历史仍由摘要与持久化来源承接，不承诺无限上下文。工具调用与结果保持配对。

跨进程 resume 从已持久化的请求快照恢复用户需求来源，逐条比较完整消息的 wire 摘要。正文或协议元数据不匹配时不恢复该标签；摘要、纠偏等 user 角色消息不因此升级为原始需求。当前输入单独标记，后续压缩沿用同一保留规则，无需新增数据库或第二套历史。

## 与 Codex 的对应关系

- `core/src/session/turn.rs`：需要后续模型动作或有待处理输入时继续；必要时压缩后继续。本轮移除了 Golutra 在此之外的隐式次数截止。
- `core/src/responses_retry.rs`：采样请求的明确连接失败可以无限等待，其他错误仍按类别有限重试。Golutra 继续复用统一 ProviderSession，使所有适配协议共享恢复边界。
- `core/src/tools/parallel.rs`：按工具能力控制并发。Golutra 保留现有只读、进程及独立路径的调度与取消传播。
- `core/src/client.rs::get_incremental_items`：增量请求复用要求请求属性和历史前缀匹配；这不是任意兼容网关都支持的能力。

当前保持完整响应后执行工具的边界。连接恢复不会重跑已完成工具；进程崩溃后的未知副作用仍需对账，不宣称全局 exactly-once。服务器压缩、WebSocket 增量请求和流中提前派发仅在支持能力与测量收益明确后采用，不为形式对齐新增第二套运行时。

传输优化的采纳门槛沿用 [上一轮实测](long-task-comparison-2026-09-19.md)：19 个工具就绪至响应结束的样本合计 1036 ms，中位数 8 ms、最大 455 ms；同一任务总计约 243.5 s。该数据不足以支持为此加入流中执行及回滚机制，因此本轮不新增。只有后续测量显示它成为主要瓶颈，且上游具备相应能力，才重新评估。

## 验收方法

确定性验收穿过旧阈值：300 次工具调用、20 次参数错误后修复、12 次验收纠偏、超过 8 次文本续写、超过 5 小时虚拟断网、重复压缩时摘要遗漏用户要求、已完成写入不重放、子代理槽位复用及恢复、显式预算和取消仍可停止。

真实对照复用独立验收器与不可修改的测试文件。`scripts/compare_continuous_tasks.py --single-task` 将四阶段工作作为一次任务提交：多文件实现、严格及容错加载、事务合并、原子写入、校验和 checkpoint、后台进程和恢复计数。运行中不注入修复提示，只有产物独立验收、运行时终态及进程状态同时通过才计成功。测试宿主有终止超时，Golutra 的任务本身不设置时间预算。

虚拟时间恢复、真实编码对照和真实多小时编码是不同证据。本轮结果见下方记录，不能用恢复测试或单个模型样本声称全面超越 Codex。

- Python 基准工具 71 项、Python SDK 14 项、TypeScript SDK 9 项及类型检查通过。Schema 与两种 SDK 类型已同步生成。
- Clippy 使用 `-D warnings`，格式与 diff 空白检查通过。

验收中修正了固定失败 mock 对旧默认上限的依赖；这些夹具现在显式设置预算。新增原始需求后同步修正 resume 测试中旧的摘要来源下标。一次 localhost 502 来自测试进程继承的代理，清除代理变量后通过，生产逻辑不因此变更。

实机平台为 macOS 27.0 arm64；没有执行 Windows/Linux 实机验收，也没有在本轮重跑数小时真实编码或两小时真实断网 soak。

## 真实同模型对比

两轮均为 `gpt-5.6-sol`、`medium`、同一 Responses 上游；第一次 Codex 先运行，第二次 Golutra 先运行。实跑 Codex 为 `0.155.1`，与前文阅读的源码快照 `fc269b66` 分别记录。未发布新的 npm 版本。

Golutra release 二进制 SHA-256：`b3f34437262a0e627c6ab34ad9ee53867d3f6eed5fff1ca63fbde8645bf159ba`。

| 轮次 | 产品 | 四阶段独立验收 | 耗时 | 原生工具调用 | 输入 token（含缓存） | 输出 token |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| Codex 先行 | Codex | 4/4，通过 | 176.0 s | 13 | 310851 | 12108 |
| Codex 先行 | Golutra | 3/4，失败 | 156.7 s | 24 | 103097 | 10841 |

| Golutra 先行 | Codex | 4/4，通过 | 166.6 s | 13 | 299494 | 11054 |

完整任务成功率为 Golutra 1/2、Codex 2/2。第一轮 Golutra 在探针运行期间完成实现并正确回收了进程，但之后又修改 `checkpoint.py` 的零计数处理；最后一次修改晚于探针终止，违反要求的生命周期顺序。这一轮 runtime 正常结束，独立交付验收失败，两者单独计分。轨迹中没有上下文压缩、网络重试或工具调度乱序；现有提示词已要求终态后不再修改受约束文件。不能将该失败归因为本轮取消预算，也不应为这个基准增加专用运行时规则。

第二轮双方成功时，Golutra 耗时更长、原生工具调用更多，输入 token 较少。未缓存输入分别为 16850 / 24567；输出 token 则为 13645 / 11054。原生工具计数的粒度不同：一个组合 shell 调用与一个独立文件读取并不等价。失败样本不记作成功提速；两个样本也不足以证明普遍速度、成本或质量优势。本轮没有同提示的旧版 Golutra 配对，因此不能把产品间差异归因于本轮改造。

本轮 21 个 Golutra 工具就绪至响应结束样本合计 706 ms，中位数 2 ms、最大 139 ms，继续不支持为提速加入流中执行与回滚机制。下一步质量重点是完成前对原始要求及执行顺序的核对；能够形式化的业务要求可使用已有项目/外部验证器，把实际失败反馈给原任务，默认不额外增加一个模型裁判或固定纠偏轮数。

验收脚本复查发现，原有第四阶段判题器只验证第四阶段，并不累计验证前三阶段。新增单任务模式现逐一运行全部四个判题器；第一轮双方原始产物已按同一规则重新判题，结论如上，原始记录保留。未修改候选产物、验收标准或不可变测试，也未向代理追加修复回合。

可复核的脱敏数据见 [两轮结果](benchmarks/2026-09-20-unlimited-continuous-tasks.json)，包含二进制、夹具、提示摘要、逐阶段结论、用量和工具派发时序。原始本机记录：`/tmp/golutra-unlimited-comparison-1.json`、`/tmp/golutra-unlimited-comparison-1-rejudged.json`、`/tmp/golutra-unlimited-comparison-2.json`。

复现命令（交换 `--engines` 顺序再运行第二轮）：

```sh
python3 scripts/compare_continuous_tasks.py \
  --single-task --engines codex golutra --timeout 600 \
  --golutra target/release/golutra-agent \
  --codex-model-catalog "$CODEX_HOME/models_cache.json" \
  --output /tmp/golutra-continuous-comparison.json
```

`--codex-model-catalog` 用于本次兼容上游：临时副本禁用 Responses Lite，用户原配置不变。未设置 `CODEX_HOME` 时需提供实际模型目录路径。凭据仅复制到临时私有目录，并由脚本在结束时清理。
