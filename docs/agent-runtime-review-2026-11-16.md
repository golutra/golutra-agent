Codex 参考仓库只更新了远程引用，没有切换本地工作树。其 `origin/main` 更新到
`cd1805370610e71eae7819b4ed28b90679a53f0e`。本轮实际阅读了该提交的
`codex-rs/ext/guardian-v3/src/host.rs` 与 `housekeeper.rs`：

- 每个根线程由一个 worker 持有游标，用户输入和回合结束的唤醒合并。
- 先刷新持久历史，再顺序处理证据；结果载荷计入预算。
- 退出时取消并等待 worker，已经接受的证据写入要完成。

这些原则与 Golutra 现有的宿主所有权、持久收件箱、批次续跑和有界退出相符。
本轮沿用这些机制，重点修复结果解释和边界衔接；未移植 Guardian 的私有辅助模型线程，
也未增加主动用户通知。另核对了 `776bd46f0` 的权限兼容辅助逻辑集中化方向，
没有据此放宽 Golutra 的执行权限。

## 已修复的问题

| 触发条件 | 修复前 | 修复后 |
| --- | --- | --- |
| 后台结果的结构化事实超过 32 KiB | 整个事实对象被截断标记替换，退出码和浏览器恢复状态丢失 | 复用前台投影优先级，先保留状态/控制字段；完整原文仍保存在 artifact |
| 浏览器页面数据字段很多，或错误摘要很长 | 字段数量限制和最终摘要回退可能丢失实际后端、待切换后端、未知结果等信息 | 初始投影、压缩、最小回退共用控制字段优先级；摘要按剩余 JSON 字节预算截取 |
| 后台操作在启动回执返回前已经结束 | 回执 `result_pending:false` 导致运行时跳过真实结果；失败可能仍按接受成功验证 | 按后台调用身份识别启动回执，归并真实结果且只更新一次 |
| 浏览器后台操作交给用户 | 持久结果为 `waiting_for_user`，但内存仍保留执行中的成功回执 | 消费结果时替换回执，保留等待用户状态，成功回执转为阻塞；不触发自动继续 |
| 上下文压缩只缩短最近消息组、没有移除历史组 | 持久化层仍强制解析不存在的摘要，子代理在第一个工具启动前失败 | 仅允许没有摘要来源、没有丢弃消息且消息数量一致的无摘要记录；损坏/缺失历史摘要仍拒绝 |
| 停止信号在进程创建前到达 | 底层普通错误向上传播，造成取消误报为执行失败 | 内部启动结果明确表示未派发取消，上层返回 `Cancelled`，不创建进程或文件副作用 |

没有更改数据库迁移、公开工具参数或 SDK 协议。本轮的状态归并不重新执行工具、
不新增会话、不重置任务预算。`browser_backend` 的会话选择、Ego 优先和安装前确认规则保留。
