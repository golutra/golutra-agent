## 已实现

| 目标 | 实际行为与边界 |
| --- | --- |
| 统一结果交付 | 子执行派发前登记到现有持久批次，共用 shell/浏览器的 Inbox、批次封口、唤醒与消费确认；保留子代理自身执行器和默认十个额度，不占十六个后台工具执行名额 |
| 静默异步 | 结果先入库；新用户输入优先携带结果，无输入时本批结束后最多继续同一循环一次；取消、暂停、接管、未知结果、需要用户输入不获得自动继续资格 |

| 去重和验证 | 按 child session + task 区分执行；已经进入父请求的终态只补简短交付确认，不重复正文或验证状态计数；上下文和 artifact 持久化之后才确认消费 |
| 提问 | 子 `ask_user` 返回 blocked、问题和来源身份，父代理承接；回答必须匹配 task/question，过期、已取消或已换代的答案被拒绝；原工具白名单和权限仍有效 |
| 等待 | 父输入可以打断 wait，保留输入且不取消子执行；超时、结束等待与取消分开 |
| 消息与续跑 | `queue_only` 只入持久消息队列；显式 `continue` 向活跃子执行补充或在同一 session 续跑；不指定模式保留旧 active-only 语义；重试去重和换参数拒绝 |
| 身份与发现 | 名字在父会话内唯一；持久注册表按游标分页，模型每页最多16；TUI每页32；邮箱最多128条、每条8 KiB |
| 文件协调 | 同 host 不同 session 的重叠规范化路径写入串行，从 before-image 到真实进程回收/比较持有资源；不相交路径和 worktree 可并行；委派自身不锁整个任务 |
| 查询缓存 | 全局锁只访问缓存表，数据库读取使用每会话锁；受管终态清除旧启动事实，历史边界清理已发布旧通知；不丢未交付 legacy 结果 |
| TUI | `/agents` 的列表、翻页、详情、取消、继续、打开；详情保留父会话，取消校验父控制者及具体执行，继续由父代理治理；固定会话 Driver 禁止 open，task-bound Driver 仅能查看 |

## 测试中发现并修复

1. 关闭子代理递归工具时曾同时移除消息接收后端，导致邮箱正文没有进入子请求。将执行后端与接收通道分开，仍禁止递归委派。
2. 较大异步状态嵌套导致默认线程栈溢出。LLDB确认回归子命令经过相同派发链叠加；子执行panic捕获和重型命令分支分别装箱。没有提高 `RUST_MIN_STACK`。
3. 并发进程启动下，复制/继承的文件描述符可能在原句柄关闭后保留 flock。执行租约最后一个 Arc 持有者显式解锁；测试在复制描述符仍存活时检查后台恢复。
4. 新文件资源等待需要遵守取消和deadline，验证器准备阶段也纳入该边界，等待时间计入执行超时；超时或取消前不启动进程。
5. Driver原有会话固定检查需覆盖新入口 `/agents open`；旧子问题需同时核对 blocked 状态和执行/问题身份。
6. 旧进程取消测试在固定20ms后取消并把冷启动计入一秒上限，在全量并发时失败。首次改用进度输出又被50ms节流延迟至进程退出；最终改为子进程写出ready文件后取消，保留一秒回收要求，没有放宽产品超时。
7. 同端口重启测试出现daemon未就绪，检查发现先预留端口、关闭再启动的竞争窗口。夹具改为先让daemon绑定随机端口，再复用其实际地址验证重启；完整server进程测试重新通过。

主要集成断言包括：

- 父同时派发真实shell、浏览器失败替身及两个真实托管子会话；只执行四次派发，副作用文件只写一次，浏览器只调用一次，父收到同一批四个结果，失败保持失败，没有重复执行。
- 子会话排队消息不启动新task；continue保持session并新建execution；相同调用重试不再次执行，变更参数、旧task和旧question被拒绝；消息在快照落盘后只确认一次。
- 父wait被输入打断后子仍可运行；取消必须来自父控制者且匹配child task；子内部后台结果不会混入父Inbox。
- 16个外部子执行不会耗尽16个工具执行名额；未知重启结果不重放；父取消、暂停、handoff和批次代次继续沿用通用后台测试。
- 真实监督shell结束前其他session不能取得旧before-image；验证器等待资源时取消/超时均不产生文件副作用。
- 实际TUI子进程通过stdio Driver显示简洁 `/agents`，拒绝切换固定session并正常退出；另有真实PTY和通用Driver回归。

浏览器为确定性协议替身，provider使用mock；没有在本轮声称真实Chrome/Ego或真实模型端到端已经通过。历史浏览器实机记录见各自文档。

## 长历史观测

`history-metrics.log`：同一隔离SQLite会话写入5,100条事件（1,700组受管执行事实），首次构建索引101,409µs；随后100次查询P50为61µs，P95为177µs。保留1条事实，计入缓存预算的payload估算258字节，游标覆盖全部5,100条事件；未变历史复用同一索引对象。注册表另验证35个子会话跨16条分页，无重复、无遗漏，其他父不可见。

这些是本机一次debug测试的合成观测，没有改造前同口径对照，不能推导生产性能倍数。258字节不包含对象开销或进程RSS；未测长期峰值内存。超大未解决legacy单轮历史仍可能重建全量索引。

## 保留的限制

- 文件协调只在同一host进程内；同session仍由已有批次调度负责，没有跨host文件锁或严格FIFO公平性保证。自动worktree合并未加入。
- 仍为单层子代理。子工具可以异步；子代理不能递归创建更多代理。
- durable重放使用稳定身份和确认，不能称分布式 exactly-once；结果投递重试不会重跑工具副作用。
- 子审批和认证仍保留原保守处理，本次没有新建跨会话授权弹窗或放宽权限。
- schema 9会让仅支持7/8的旧实例拒绝共享数据库；升级必须结束旧实例并更新内核，未对用户实际home执行迁移。
- 本机为macOS；Windows/Linux实机、真实模型长时运行和跨进程文件竞争未在本轮验证。
