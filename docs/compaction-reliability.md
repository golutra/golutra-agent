# 摘要完整性与失败恢复

自动压缩和 `/compact` 共用 runtime 的 `CompactionSummaryPlan`。context crate 负责历史区间、保留消息、摘要封装和预算内安装；runtime/client 分别负责执行请求及同步/异步审计。协议适配器只提供标准化的响应和结束原因，不维护各自的压缩策略。

## 本次修复依据

2026-09-22 提供的会话中，四次摘要请求都以 `length` 结束，实际输出均为 2024 token，随后使用 `fallback_facts_tail`。输入 usage 分别为 89847、83006、86588、89421 token；四次请求合计约 99 秒。原请求把最多 2048 token 的摘要保存额度扣除消息开销后直接作为模型输出上限，提示词未告知目标篇幅。

这不是整个一小时任务的唯一或主要根因；执行完成与验证纠偏循环属于独立修复。四次摘要都失败也不能证明之后的每次重复工具调用由摘要丢失导致。

## 三种预算

| 预算 | 默认行为 |
| --- | --- |
| 保存容量 | 自动摘要消息最多 4096 个本地估算 token，包含消息前缀；显式摘要封装最多 4096。小窗口会进一步缩小自动摘要容量，并保留最近消息空间 |
| 正文目标 | 从封装容量预留 128 token 后取 75%，约 3K；实际请求再受生成额度的一半约束 |
| 生成上限 | 首次请求为封装容量的两倍，约 8K；截断后重试至多提高到 16K。两次请求都受当前模型/用户配置的 max_output 和剩余窗口约束 |

生成额度给正文与可能计入输出的推理 token 留余量，不等于要求模型写满该额度。不同协议的 usage 归一化保持不变，不从可见文本长度推断 reasoning usage。

本地 token 仍使用项目现有字符估算，不等同于模型 tokenizer。日志中四次摘要输入估算约 40–43K，而上游 usage 约 83–90K；本次未替换全项目 tokenizer。最终真实服务上的语义保留率与最佳默认预算仍需实测，4K/8K 是当前有界默认值，不是普遍最优值。

## 生成、验收与安装

提示词按“目标与约束 → 剩余工作 → 当前状态与证据 → 关键决策”组织，要求合并重复尝试、区分验证事实与声明，不逐条复制旧日志或所有校验值。

只有正常 `Stop`、无工具调用、非空且完整封装能放入保存预算的模型摘要才能替换历史。封装大小包括 JSON 转义和来源信息。即使上游正常结束，正文过大也不能在本地截取前缀后当作成功摘要。

| 结果 | 处理 |
| --- | --- |
| 完整且能保存 | 安装完整摘要，保留来源、最近历史和完整工具调用/结果组 |
| `Length` | 从同一份原始历史重新生成一次，更短的正文目标；窗口与配置允许时提高输出余量 |
| 正常结束但保存超限 | 从原始历史重新生成一次，更短的正文目标；不额外提高生成上限 |
| 再次截断或超限 | 使用已经建立的本地备用摘要 |
| 空回复、非正常结束、工具调用、输入超限、请求失败、超时 | 不做长度修复，使用本地备用摘要；连接级恢复仍属于原有 transport 策略 |
| 用户取消 | 停止请求，不继续摘要，不提交新的压缩边界 |

长度修复最多一次，只限制辅助摘要操作，不限制主任务迭代数。重试不会把不完整的模型摘要当作事实来源。摘要请求不启用工具，也不把中间正文显示成主任务回复；各次请求独立记录请求身份、预算、usage 和结束原因。

## 备用压缩

先单独寻找最新的上一份摘要，再有界收集最近事实。最近日志填满预算后提前退出，不再导致位于历史前部的旧摘要被漏掉。

备用摘要仍是有损、预算受限的应急投影，不能保证无限历史无损。完整事件和工具产物继续保留，成功生成的模型摘要则禁止静默截断。既有原始用户要求保留、权限可见性和工具配对规则不变。

后续回合加载已保存的摘要时也保留完整封装，不再另设 2K 上限并截取前缀。切换至更小窗口时，完整摘要和最近保留额可以使初始投影超过目标预算，由 runtime 统一重新压缩或报告容量不足；client 不提前丢掉摘要尾部来伪装预算满足。

`CompactionCompleted` 新增：

- `summary_attempts`：准备并执行的逻辑摘要请求次数，通常为 0、1 或 2；不等同于底层 HTTP 连接重试次数。
- `summary_failure`：最终降级原因；模型摘要成功时为 null。每次失败的 provider 结束原因和真实错误仍保留在相应事件中。
- `compaction_id`：本次压缩 attempt 的身份；`CompactionStarted`、`CompactionFailed`、`CompactionCompleted` 以及 baseline artifact 使用同一值，resume 或审计不需要按相邻事件猜测生命周期。
