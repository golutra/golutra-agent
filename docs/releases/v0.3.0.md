## Golutra Agent 0.3.0

This release separates Agent installation and data from the Golutra desktop app,
improves background work and terminal interaction, and provides native archives
for offline desktop bundling.

### Install or update

```sh
npm install -g @golutra/agent@0.3.0
golutra-agent --version
golutra-agent
```

The root package selects the matching native package for Windows, macOS or Linux
on x64 or ARM64. Desktop applications can bundle the native archives directly;
Node.js and npm are not needed to run those archives.

### Highlights

- `/login` opens the same provider setup as `/auth`. `/logout` clears the active
  provider configuration and local credential and opens setup again; history and
  other provider profiles are retained. Shell environment variables are untouched.
- Custom providers can explicitly select OpenAI Responses. Model changes persist
  across restarts, and reasoning levels include lowercase `max` and `ultra`.
- Tool cards show short command output and readable file changes with line
  numbers, addition/deletion counts and red/green rows. Ctrl+O opens searchable
  saved details, including after resume, without issuing another model request.
- Native terminal selection is preserved. Long responses, history, status output
  and window resizing have dedicated terminal regression coverage.
- Background subagents have configurable concurrency (default 10), execution-bound
  cancellation and continuation, batched waits, and corrected token accounting.
- Native/npm artifacts share the same binaries. The attached desktop inventory
  records platform, architecture, source revision, download URLs and SHA-256 hashes.

### Breaking changes and data

- Use `golutra-agent` and `golutra-agent-tui`. Old `golutra` command aliases are
  not installed; the desktop application's own command is not modified.
- Agent configuration uses `GOLUTRA_AGENT_HOME` (default `~/.golutra-agent`) and
  `GOLUTRA_AGENT_*` variables. Project runtime settings use `.golutra-agent`.
- Old homes and credentials are not copied automatically. Obsolete database or
  provider formats are rejected without migration. Configure a fresh Agent home
  when upgrading from an incompatible version; retain old data separately.
- Matching current desktop/npm Agent builds can share configuration and history,
  but cannot take over the same running session concurrently. Desktop payloads
  update with the desktop; npm installations update through npm. Uninstalling
  either payload does not remove shared data.
- The built-in web search tool remains unavailable; external plugin/MCP tools
  are supported.

### Validation and artifacts

Before the version bump, the included configuration and TUI changes passed 490
tests, with one live-provider smoke test intentionally skipped. Release jobs run
on each target OS/architecture and require npm installation, native launch without
Node/npm on PATH, shared-data checks and obsolete-version rejection before
publication. Native-runner smoke tests do not replace acceptance in every user's
terminal or a signed desktop installer.

Windows 0.2.0 cannot open even an empty home because its SQLite URL handling is
broken. Windows reports therefore explicitly mark the legacy baseline unavailable:
0.3.0 native execution and shared-data tests are required, and a synthetic old-schema
fixture must be rejected without changes. A successful Windows 0.2.0 creator and
bidirectional format-boundary run could not be verified. Unix uses the real 0.2.0
binary for both directions. This release does not support running mixed versions.
