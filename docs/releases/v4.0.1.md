## Golutra Agent 4.0.1

This patch release fixes provider capacity recovery and Windows execution,
including the changes in [PR #56](https://github.com/golutra/golutra-agent/pull/56).

### Install or update

Requires Node.js 20.18.1 or newer.

```sh
npm install -g @golutra/agent@4.0.1
golutra-agent --version
golutra-agent
```

### Fixes

- Confirmed provider capacity errors now use the existing retry budget instead
  of immediately failing the turn. The two default retries wait 5–5.5 seconds
  and 15–16.5 seconds; server retry advice takes precedence. Cancellation,
  deadlines and permanent-error boundaries remain in force.
- HTTP and SSE adapters preserve the same capacity classification. False/null
  flags, echoed input and unrelated diagnostics do not enable capacity retries.
- CLI and runtime dispatch use bounded stack space, preventing browser and
  embedded execution commands from overflowing Windows' default stack.
- OpenCLI's Windows Node entrypoint preserves the canonical script target.
  Failed version probes report bounded, redacted diagnostics and preserve the
  saved browser configuration.
- SDK schema-generation dependencies no longer include the reported vulnerable
  dependency chains. Generated protocol types remain unchanged.
- Real-terminal tests wait for visible status and tool-detail states, preserving
  their ordering and selection checks under slower CI scheduling.

### Compatibility

This release keeps the 4.0.0 configuration and data schema. It adds no migration.
If upgrading from a version before 4.0.0, read the
[shared-data upgrade requirements](https://github.com/golutra/golutra-agent/blob/v4.0.0/docs/releases/v4.0.0.md#data-compatibility)
and update other runtimes sharing the Agent home.

### Validation and distribution

The implementation included in this release passed all eight
[PR CI jobs](https://github.com/golutra/golutra-agent/actions/runs/44284703291)
on Linux, macOS and Windows: 2,396 Rust tests passed with 10 explicit skips,
alongside 9 TypeScript SDK tests, 10 browser/launcher tests, 39 Python packaging
tests and 14 Python SDK tests. Strict Clippy, generated protocol checks and the
SDK dependency audit passed; the audit reported zero vulnerabilities. Local
browser and embedded-execution process suites also passed with a 1 MiB main
stack. Provider fixtures do not establish live cloud-provider availability.

The release workflow separately builds Linux, macOS and Windows x64/arm64
artifacts and verifies installation, native execution, shared data compatibility
and npm/native payload parity before publishing the root package and all six
platform packages at 4.0.1. SDK metadata is aligned; no new public SDK package is
published.
