# Inline 聊天与全屏工具详情

交互入口 `golutra-agent` / `golutra-agent-tui` 默认使用普通终端上的 inline 聊天。Logo、用户问题、助手叙述、工具摘要和本地命令结果依次进入终端历史；活动输出与输入框留在 inline viewport。启动时不进入 alternate screen，旧 `--inline` 参数仅为兼容保留。

主聊天和工具详情均不捕获鼠标，文字选择、复制及鼠标滚轮交给终端，不提供卡片悬浮、点击打开或应用内拖选。采用 Pi 的 `Ctrl+O` 工具输出快捷键：打开最近工具的全屏详情，再按一次关闭，`Esc` 也可返回；左右方向键切换工具。这里借鉴按键约定，Pi 本身是在聊天内批量展开/收起。已有 /resume 等选择器继续使用临时全屏交互。

`/auth` 认证向导保持全屏，但仅用方向键、数字键和 Enter 选择，Esc 返回上一步，PageUp/PageDown 滚动；不捕获鼠标，拖选和复制交给终端。全屏状态与鼠标捕获分别管理，认证页与帮助页切换、窗口缩放及终端挂起恢复都保持各自的鼠标策略。

`/login` 是 `/auth` 的别名，前缀候选显示 `/auth (alias: login)` 并可直接回车进入。`/logout` 无参数：通过配置事务删除当前 Provider 条目及本地凭据，保留其他 Provider、设置和历史，随后打开全屏向导；最后一个条目删除后按现有事务规则移除空的 `provider.json`，不删除整个数据目录。环境变量凭据仅解除引用，shell 环境不变。OAuth 远端撤销失败会保留警告并继续本地退出；配置并发变更或本地清理失败则显示错误。旧会话的 Provider/模型覆盖同时清空，权限选择保留。现有 `/auth logout [profile]` 仍只停用条目和移除凭据。

`/model` 直接进入模型编辑框。编辑状态下 Esc 保留修改并返回设置列表；列表里上下选择，Enter 编辑模型或调整选项，Esc 应用设置并返回聊天，不需要 `e` 键。编辑时 Enter 或任意设置状态下 Ctrl+S 也可直接应用退出。Ctrl+U 清空输入；空值或超过 256 字符的模型名保持编辑状态并显示错误。这两个入口同样不捕获鼠标，文字选择和复制交给终端。已处于 unrestricted（包括 `--yolo`）时修改模型不重复确认权限；从 guarded 改为 unrestricted 才要求 Enter 确认；确认页按 Esc 保存其他设置并保留原权限。任务执行期间仍锁定运行时设置。

本地运行时，模型选择立即用于当前会话，并保存到 `$GOLUTRA_AGENT_HOME/runtime.json`，重启后继续使用；若项目已存在 `.golutra-agent/runtime.json`，则更新该项目层，避免旧的项目覆盖使模型还原。显式切换 profile 时同时保存对应选择。保存复用锁、revision 校验和原子文件替换，只修改模型相关字段，不改写凭据、provider 定义或权限；失败时保留编辑框及草稿，不假报成功。`/model <model-id>` 使用同一机制。远程 TUI 保持会话覆盖，不写本地配置冒充修改远程主机。

选择 `3 Custom Provider` 后，协议依次为 OpenAI Responses、Anthropic-compatible、Gemini-compatible、OpenAI Chat Completions、Vertex AI、rust-genai。Responses（`/responses`）与 Chat Completions（`/chat/completions`）是独立协议，不自动互换；根据服务商支持的接口选择。确认页 Enter 只在本地校验并保存配置和凭据，不探测模型、不发送联网验证请求；保存成功后返回聊天输入，实际连通性由后续模型请求验证。`/auth login` 使用相同保存路径；本地保存失败则保留向导并在确认页顶部显示错误。保存的协议决定后续生成请求使用的接口。

API Key 配置默认直接进入密钥输入页，保存到 `$GOLUTRA_AGENT_HOME/credentials.json`，不再单独询问存储方式。在该页按 `Ctrl+E` 可切换到环境变量名称输入，再按一次切回本地 API Key；切换时清空密钥和旧确认计划。环境变量名称初始为空，不自动生成或补全，留空继续会提示填写；只保存用户输入的变量名，不创建或修改环境变量，须在启动 Agent 前设置。Esc 返回地址页，保留所选模式与手填变量名；从模型页返回时回到对应凭据输入页。确认页仍显示真实凭据来源，自定义配置共六步。

Base URL 可填裸域名（默认 HTTPS）或完整基础地址。OpenAI Chat Completions、Responses、Anthropic 在没有路径时补 `/v1`，Gemini 补 `/v1beta`；已有版本号、自定义代理路径和 ChatGPT 的 `/backend-api/codex` 保持原样。按所选协议识别完整的 `/chat/completions`、`/responses`、`/messages` 或 Gemini `/models/<model>:generateContent` / `:streamGenerateContent` 地址，去掉操作后缀以避免重复拼接；实际模型仍以 Model 字段为准。带凭据、查询参数或 fragment 的地址拒绝保存。Vertex AI 需要明确的项目/区域基础路径，不能从裸域名猜测；rust-genai 按其已有模型路由为 OpenAI、Anthropic、Gemini、DeepSeek 补默认路径，其他路由要求明确 API 基础路径。确认页和保存内容显示规范化地址，运行时对已有配置及环境变量使用同一规则，不联网尝试多个端点。

`/auth` 明确保存或切换 provider 后，当前会话采用新 profile 的模型与推理设置，同时更新全局及当前已存在的项目 runtime 设置层中的对应选择。即使复用 `custom` 等同名 profile，也不会保留旧 `/model` 覆盖导致新协议搭配旧模型；下一次请求和重启后都使用新选择。权限、工具设置及子代理并发配置保持原值。普通状态刷新继续保留用户当前 `/model` 选择。

Reasoning effort 在设置页和认证高级配置中的顺序统一为 `default → low → medium → high → xhigh → max → ultra`，界面、配置和请求值均使用小写；`/effort max`、`/effort ultra` 同样可用。Responses 和 Chat Completions 按显式选择发送原值，具体模型是否接受由上游决定。`ultra` 是网关扩展，当前 Genai 原生适配器不支持时明确报错，不自动降档；`max` 在其他原生协议中沿用依赖库的协议映射。

输入 `/` 时，在输入区显示最多 5 个常用命令及简短说明：`/help`、`/model`、`/resume`、`/status`、`/new`。继续输入按前缀筛选；方向键选择，Tab 仅补全，Enter 执行或进入参数填写。第一次 Esc 收起候选并保留草稿，不中断正在运行的任务；继续编辑会重新筛选。普通命令进入参数填写后不再显示命令名候选，`/auth` 与 `/debug` 支持子命令补全。

候选高度按实际描述换行计入 inline 活动区，显示预算为 8 行；普通命令仍最多提供 5 个候选。候选与普通模型/工作区底栏共享空间，打开时底栏替换为选择、补全、确认和关闭提示。小窗口优先保留输入与操作提示，候选窗口包含选中命令开头。测量与绘制共用 `CompletionPopupLayout` 的物理行。命令候选完全在本地生成，不请求模型。

主屏活动区从当前顶部锚点向下增长；空间不足时才通过原生滚屏将历史上推。候选过滤、Esc 收起及多行草稿缩短后保留顶部锚点，不反向下移历史、不强制贴底。暂时空出的空间由新内容自然消耗。这一规则同样适用于极小窗口，避免历史和下一条消息之间出现人为填充的空白。

## 架构

| 层 | 实现 | 职责 |
| --- | --- | --- |
| 持久历史 | `history_source.rs`、runtime store | 分页读取真实事件；恢复与交互共享 32,768 事件 / 32 MiB 预算 |
| 语义投影 | `transcript_view.rs` | 保留叙述与工具顺序，合并相邻读取/列表/搜索，保留执行、修改、失败和已归档边界 |
| 主屏归档 | `inline_history.rs` | 原生历史只追加，稳定流式前缀提交，最终修订明确标记，不发送清空 scrollback 指令 |
| 可见历史 | `resize_visible_history` | 只缓存一屏应用行，物理窗口缩放时重画可见区域；候选扩缩不触发重放，保留 shell 前缀 |
| 终端视口 | `managed_terminal.rs` | 持有同一 Backend 和绘制缓冲区，统一活动区扩缩、历史插入和临时全屏定位；仅启动时查询光标 |
| 工具详情 | `tool_detail.rs`、`tool_detail_data.rs` | 异步读取持久 artifact、校验、排版缓存、键盘搜索/滚动/返回；原生鼠标选择 |
| 文件差异 | `tool_preview.rs`、client change tracker | 由历史 unified diff 的 hunk 计算真实旧/新行号，避免读取当前文件重建旧修改 |
| 展示布局 | `transcript_widget.rs`、`render.rs`、`session_banner.rs` | 共享换行与语义渲染，响应式页首和活动区布局 |
| 终端生命周期 | `draw_interactive_frame`、`OverlayScreenState`、`terminal_integration.rs` | 同步归档/绘制，保存主屏 viewport，临时切换备用屏，退出和异常恢复 |

归档正文与行身份事务性提交，写入失败时不推进归档游标。工具摘要是否简洁由独立展示策略控制，不依赖是否全屏。

流式显示按内容复用解析与排版：`rich_text/cache.rs` 保留稳定语义块，可变尾部交给原 Markdown 解析器；新块首行收完整后才推进稳定边界，避免部分表格行造成过早冻结。后置引用定义或 HTML 等跨块状态回退完整解析。未变化块复用排版，增长代码块保留已完成行，仅重排最后一行和新增内容；最终正文修订及宽度变化重新计算。历史归档共用解析器记录的源边界，并校验渲染前缀。按宽度区分缓存，最多保留 32 份文档、累计 2 MiB 源码；超预算内容走完整渲染，不截断正文。

换行阶段借用源字素，输出行形成时才分配文本；保留样式、组合字符和中文标点避头规则。交互 Backend 使用标准库缓冲写入以合并细碎字符/样式，帧结束和光标查询前显式 flush，继续用同步更新保护显示。参考实现与选择记录见 [Codex/pi 对比](benchmarks/2026-09-21-tui-codex-pi-comparison.md)。

普通键入不重新归档未变更的历史；原生 scrollback 已接收的完整条目保留事件身份，不再排版。活动区高度与正文绘制共享本帧布局，事件投影按 revision 和命令锚点复用；正文、归档边界或宽度改变会重新计算。输入框布局按文本编辑、光标位置和宽度失效，撤销、重做和重置使用同一规则。

首次 `@` 文件扫描在可取消的后台线程运行，结果用当前草稿重新匹配，工作区切换后丢弃旧扫描。交互事件批次最多 32 个，并在每个事件之后检查 2ms 时间预算；单个事件不能抢占，剩余事件保留 FIFO，无需等待新网络数据就会继续处理。绘制、键盘和 Runtime 三个就绪来源轮转优先级。120 FPS 是刷新上限，不是固定轮询间隔。Offscreen driver 继续完整同步快照。

历史 payload 在新事件入队或回放加载时约束大小；总字节数在新增、替换和裁剪时记账，预算检查不再周期性序列化整段历史。连续同回合文本 delta 原地追加到活动正文投影；工具、重试、最终修订、历史替换和语义边界变化回退完整投影。仅行归档和布局变化不再废弃事件投影。

对照 Codex 的稳定行队列做过逐行提交实验，但在当前原生历史与实时尾部预览上增加了等待：同条件突发场景 P95 从 31.72ms 上升到 67.22ms。因此不保留排队动画或隐藏开关，稳定前缀继续按帧批量归档，未换行正文实时预览；使用事件工作预算和公平调度避免 UI 饥饿。实验与最终实现分别记录，不能把撤回的候选结果当作最终效果。

可选诊断 `GOLUTRA_AGENT_TUI_TIMING=/绝对路径/新文件.csv` 记录事件、批次、投影、历史、帧、输出 flush、输入和快照应用耗时。仅保存最近 16,384 个阶段样本；没有正文、按键或凭据，热路径不写磁盘，正常退出时用 create_new 写出，已有文件会明确报错。未启用时不收集样本。复现实测见 [基准工具](../scripts/tui_benchmark/README.md) 与 [稳定性验收](benchmarks/2026-09-21-tui-stability.md)。

主屏不再重建 Ratatui Terminal，也不通过恢复阶段屏蔽 `append_lines` 修正位置。管理层直接更新矩形和缓冲区，继续使用 Ratatui 控件、换行算法与已有连续宽字符 Backend。一次帧更新依次处理物理窗口变化、准备稳定归档、按剩余活动尾部调整高度、写入历史、绘制活动区，整个过程仍由 synchronized update 包围。活动区在滚动前清理，候选、草稿和旧输入框不会被当作历史提交。

启动命令和已有 shell 输出不属于应用的清理范围。回复完成、输入框收缩和同一会话的布局刷新不再清空并重放整个历史。已归档的屏外内容保留原显示版本；如果最终答案确实修订了已经输出的流式正文，追加带 Updated response 标记的完整修订版本，不能为了擦除旧版本而清空用户终端。新进程 resume 使用持久化的最终事件。

启动横幅紧接 shell 输出，即使编译日志已经把光标推到屏幕底部，也不在 Logo 前补满一屏空行。归档通过自然滚屏腾出空间，不人为添加页首填充。

长代码块完成时，先准备待归档正文和提交标记，再按剩余活动尾部调整视口，最后插入历史。不能先为已完成正文保留整屏活动区、归档后才收缩，否则整段正文会被挤到屏外，下一条消息前留下整屏空白。标记与本地命令仍在同一事务内，终端操作失败时回滚。

详情页按需读取已脱敏的本地 output/diff artifact，每块 64 KiB，总读取预算 16 MiB；检查游标、长度、稳定元数据和 SHA-256 后解码 UTF-8。失败或 artifact 已过期时明确提示，不把短摘要冒充完整日志。运行时保留上限依然有效，截断时注明仅展示保留部分。进程结束后持久化保留输出，相同内容复用 artifact；保存失败不吞掉真实终态，也不改变模型读取游标。详情不请求模型，不重新执行命令，不回灌上下文。

运行中工具进入详情后保留身份边界，完成事件可更新同一页面。详情期间继续接收 runtime 事件，但不向备用屏写入主聊天历史；返回时统一归档未显示内容。正文去除 ANSI/OSC 控制序列后展示，按宽度与内容缓存排版，避免每次滚动重新处理整份日志。

## 工具分组与显示

- 相邻成功的读取、列目录、搜索可以合并；助手叙述、shell、文件修改、后台交互和失败保持各自边界。
- 混合的上层 ToolBatch 摘要不能覆盖真实工具事件中的失败或执行边界。
- 简洁摘要保留类型、状态和少量对象/命令预览，按显示宽度限制长命令；单文件读取不重复打印标题中已有的文件名。
- 命令默认附带状态、耗时和最多 5 行输出，运行时显示短尾部。文件卡片标题使用 `Edited path` / `Created` / `Deleted`，下一行用 `└ (+2 -1)` 显示统计；路径只在标题或多文件的对应段落出现。默认预览和 Ctrl+O 详情均隐藏标准补丁的文件头与 `@@`，不连续修改块以淡灰 `…` 分隔；原始 artifact 不变。
- diff 使用行号、增删符号、代码三列，行号按当前块的最大位数对齐；删除行铺红色底色、新增行铺绿色底色，上下文不加底色。长行按显示宽度换行，续行不重复行号，中文与 emoji 不拆断；缩放后保留整行底色。主聊天继续使用原生鼠标选择。
- 文件预览只截取 Diff 分区，后续 Arguments/Output/Facts 不参与预览及“更多修改”计数；只有真实差异超出预览预算才显示提示。文件修改失败时，详情仍保留失败上下文与诊断。
- `Ctrl+O` 打开最近一个工具的全屏详情，再按一次关闭；左右方向键查看较早/较新的工具。
- 卡片仅显示摘要，不响应鼠标点击。主聊天、工具详情、认证和模型设置均使用原生鼠标选择。
- 详情展示已脱敏的调用信息和持久化保留结果，失败信息不因其他调用成功而隐藏；不等于无界完整日志。
- 参数校验失败在主聊天和恢复的历史中显示 `Failed · <tool>` 与具体诊断，例如 `max_output_bytes: 20000 is greater than the maximum of 4096`；完整的有界诊断保留在详情和原始事件中。只展示 schema 已声明的顶层字段名，以及 shell 分页大小这一非敏感数值，其他参数值继续脱敏。工具请求仍被拒绝，不自动修改参数或执行失败的请求。
- 独立消息间保留一行空白，正文原有段落空行继续保留。

工具显示策略不改变实际工具次数、执行顺序、权限、失败语义或模型可见结果。模型设置的持久化仅保存用户显式选择，不改变 provider 协议或凭据。

## 滚动、复制与返回

- 主聊天使用终端原生拖选和复制快捷键，包括已有工具卡片、退出详情和恢复会话后；鼠标滚轮不触发应用历史视图。
- 启动、全屏页面返回和外部终端挂起/恢复同步当前页面的鼠标策略；/auth、/model 始终保留原生选择。
- 详情页使用方向键、PageUp/PageDown、Home/End 翻阅；默认从顶部查看，新结果不会主动推走阅读位置。
- `/` 输入搜索词，Enter 搜索，`n` 查找下一处；搜索覆盖加载的全部保留内容。标题与正文点击均不执行动作。
