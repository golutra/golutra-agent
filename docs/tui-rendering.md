# TUI 渲染与终端历史

本次重构针对用户提问被覆盖、流式中文中间帧错乱、长回复或 resume 不完整，以及 `/status` 覆盖正文的问题。参考本地 Codex `13bc770e` 的终端锚点、历史插入、流式稳定区域和 alternate-screen 生命周期；保留 Golutra 已有 runtime 事件协议与工具执行语义。

## 职责与不变量

| 层 | 实现 | 职责 |
| --- | --- | --- |
| 持久历史 | `history_source.rs`、runtime store | 分页加载原始事件，恢复时与交互窗口共用 32,768 事件 / 32 MiB 上限 |
| 语义投影 | `transcript_view.rs` | 按事件顺序组合用户消息、助手段落、工具生命周期；已经归档的工具单元不可被晚到批次摘要重写 |
| 流式边界 | `stream_commit.rs`、`rich_text` | 使用相同 Markdown 解析选项，最后一个顶层块保持可变；只有已稳定且渲染一致的前缀进入历史 |
| 消息间距 | `transcript_spacing.rs` | 独立消息间保留一行空白；同一事件的流式片段连续显示；归档与活动区域共享末行状态 |
| 历史提交 | `inline_history.rs` | 用户消息立即归档；已完成内容只提交一次；遇到活动单元停止向后归档；本地命令保留源码锚点用于重排 |
| 物理终端 | `terminal_integration.rs`、`draw_interactive_frame` | 保留活动区原锚点，空间不足时真实滚屏；归档、调整活动区、绘制在同一 synchronized update 内完成 |

普通对话使用终端主屏幕。Logo、提示、已提交的问题、回复和 `/status` 都进入原生滚动历史。底部只重绘活动内容和输入区。选择器等全屏交互进入 alternate screen；退出时恢复保存的 inline 区域，不根据新光标位置额外插入空行。

归档采用准备/提交两阶段：仅在终端写入成功后确认提交状态。失败时恢复未提交的命令和应用侧标记，由调用链如实报告 I/O 错误；部分物理写入不可逆，不自动把失败当成功重试。

## 具体修正

- 移除“始终把活动区顶部设为屏幕底部减高度”的定位方式。该方式会在增长时向上清掉已输出的用户问题；现在先清理旧活动区，再用真实换行滚屏腾出空间。
- 用户消息无需等助手回复才归档。稳定内容不同时存在于历史区和可重绘区域。
- 用户→助手、助手→用户、用户→用户、助手→助手均使用同一消息间距规则；工具卡与 `/status` 等独立单元同样分隔。现有正文空行不重复叠加结构分隔行，分隔行不计入流式正文提交游标。启动提示后也只保留一行留白。
- 不再用“除最后一个可视行之外全部稳定”判断 Markdown。表格列宽、列表、围栏和未完成段落保留在活动尾部；已提交部分不重复显示角色符号，搜索视图也不应用流式行跳过规则。
- 活动流归档时记录实际写入的渲染前缀。最终回复或后续 Markdown 定义修订该前缀时，从事件源重建历史，不能按旧行数跳过新正文；正常追加不触发重建。前缀缓存只保存尚未完成的流，收口或历史重排后释放。
- 工具批次的提交判定采用全部事件已提交；禁止把未归档的调用合并进已归档批次后整体过滤掉。后完成的独立工具不能越过前方活动工具提前归档。
- 默认工具卡显示调用摘要和失败信息；参数 JSON、文件正文及有界输出保留在详情，完整证据仍在 runtime artifact。批次摘要不销毁原始工具详情，`Ctrl+O` 可展开已归档的调用。运行中的进程另保留最多三行进度尾部。此变化只影响 TUI，不缩短模型收到的工具结果，也不改变实际读取、验证或失败语义。
- `/status` 等本地命令保留语义内容与事件/源码锚点，窗口变宽或变窄时按原位置重排。它们不注入模型上下文；关闭进程后仍以 runtime 持久事件恢复对话，本地状态快照不伪装成持久业务事件。
- 统一历史加载器与 TUI 内存预算，避免完整恢复后立刻被旧的 512 KiB 交互窗口再次裁剪。

## 验收

2026-09-14 复查后的本机结果：353 项通过、0 失败、1 项按配置忽略。其中 library 18 项、TUI binary 323 项、PTY/终端模型 5 项、跨进程 Driver 7 项通过；真实上游 live smoke 未启用。`clippy --all-targets -D warnings`、workspace `fmt --check` 与 `git diff --check` 均通过。宽屏 Logo、流式中间帧及工具归档后的 `Ctrl+O` 展开/收起均纳入真实 PTY 检查。

运行：

```sh
cargo test --locked -p golutra-tui
cargo clippy --locked -p golutra-tui --all-targets -- -D warnings
cargo fmt --all -- --check
```

真实 PTY 用隔离 `GOLUTRA_HOME`、临时工作区和 localhost SSE provider 驱动实际二进制、runtime 及真实文件工具，不访问外部模型。使用 VT 屏幕与滚动历史解析器检查可见顺序、唯一性和完整性，不能只检查原始 ANSI 字节中出现过某句话。

覆盖：40 段中文及空行、400 行代码块、流式中间帧、两个连续提问、`/status`、生成期间插入状态、窗口缩放、resume 选择器退出、关闭后新进程恢复、自然语言与两次真实读取交错、原始 JSON/HTML 不进入默认卡片。真实 PTY 同时检查独立消息前缺失或重复的空行；四种角色组合另覆盖实时布局、分次归档和重放。另有历史预算、流式 Markdown 块、最终回复修订旧前缀、晚到工具结果和终端失败不确认归档的单元回归。现有 macOS/Linux PTY CI 自动纳入这些测试。

## 边界

- 测试验证本机 macOS PTY 和受控流式输入；不等于已在所有终端模拟器或 Windows 上完成人工验收。真实上游断流仍应显示真实错误，本次不会掩盖网络或 provider 失败。
- 超出 32 MiB / 32,768 事件的历史仍有有界窗口及分页限制，不能宣称无限历史全部常驻。单条超大 payload 仍遵循既有保护上限。
- 尚未闭合的超长 Markdown 块只显示活动尾部，完整源码保留，完成时完整归档；不为提前滚屏而冻结可能变化的表格或列表布局。
- 显式历史重建和宽度重排使用现有 xterm 清屏/清滚动历史再回放路径，依赖终端对相关控制序列的支持。普通流式更新、输入区高度变化和 `/status` 不执行整段历史重建。
