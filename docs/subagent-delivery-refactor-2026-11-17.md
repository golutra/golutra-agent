# 子代理与后台结果交付重构

日期：2026-11-17，macOS / Asia/Shanghai。承接[上一轮优化与实测](subagent-optimization-2026-11-17.md)。本轮围绕结果完整性、静默交付、终答边界、子任务约定与可重复评测实施；没有提高默认并发数，也没有取消浏览器资源保护。

## 已实施的行为

| 问题 | 现在的行为 |
| --- | --- |
| 一份很长的子结果使整批短答案一起丢失 | 分别压缩长正文，保留短答案、执行身份、失败事实及 Unicode 续读位置；元数据也超预算时明确报告省略数量 |
| “读到最后一页”被当作“读过完整结果” | 统一 `child_result_coverage`；非零起点、缺失正文、截断或字符计数不一致都不能确认完整 findings |
| 父代理还在工作，却等到收尾才接收后台结果 | 当前执行的结果附带到下一次本来就需要的模型请求，每次最多 16 条；与主动唤醒权限分开 |
| 内部观察包装语进入用户答案、后台未结清就提前展示“完成” | 合成 assistant 载体为空，来源信息留在 tool 数据；后台相关无工具答复先作为候选，经过结果与验证边界后发布 |
| 延迟公开终答后子代理原始发现丢失 | 验证事件独立保存 provider findings；父代理能读取未验证发现，公开失败诊断不会替换它 |
| 自然语言“不要用工具”约束不可靠 | spawn/resume 支持明确 `tool_profile`，只能缩小父权限；续跑保留原子会话更严格的权限 |
| 分工与交付约定只藏在长提示里 | `assignment` 定义负责文件、新文件、接口、局部检查和验收；省略时续跑沿用原约定，文字验收明确保持待父代理复核 |
| 并行快慢无法定位到阶段 | 工具记录资源等待，后台执行记录排队与执行耗时；评测另统计派发、入场、模型耗时及结果交付延迟 |

暂停、取消、用户接管、旧 turn 和上下文压缩仍保留保守交付规则。新用户输入优先；没有新增用户通知。独立排队问题仍保留各自回答，steer 可以替换未公开候选。共享状态、执行取消和自动续跑权限没有合并成一个开关。

`owned_paths` 是责任与验收约定，**不是文件系统沙箱**；shell 仍受已有工作区和工具权限控制。`checks` 是交给子代理的执行约定，不会在 admission 阶段直接执行任意命令。浏览器仍保守串行，未声称任意标签页或用户 Profile 可安全并发操作。

自由文字 `acceptance` 保留为行为复核清单，结果携带 `child_acceptance_status: "requires_parent_review"` 与原条件。运行时继续验证明确交付路径、实际检查与既有显式合同，不靠关键词把复杂行为要求自动判为通过。父代理须据子 findings、整合检查及实际界面验收评估这些条件。

实现入口：[子代理](subagents.md)、[后台任务](background-tasks.md)、[可复用评测脚本](../scripts/benchmarks/subagents/README.md)。

## 真实预检与发现的回归

首次真实预检发现新任务约定会扩展子提示文本，但一次性 admission 能力绑定的是扩展前的文本，导致八个子会话已经创建、子执行全部在入场前被拒绝。运行在 65.225 秒主动取消，原二进制、事件和错误保留，未把它算作通过。

新增宿主集成测试先复现失败，再将任务约定和权限处理提前到 admission 创建之前，使授权绑定最终任务文本。没有移除身份或摘要校验，也没有放宽伪造运行时命令的拒绝规则。

修复后相同预检为 **18.363 秒**：8 个独立子会话、峰值并发 8，先计算 1² 至 8²，再在原 square1 会话续跑 9²。总计 9 次子执行都完成，工具 profile 均为 `none`，9 份持久请求快照的工具目录均为空，未创建受管 shell 进程。任务约定在续跑后保留；9/9 inbox 已确认，父代理仅一次无工具终答，返回平方和 204 与续跑结果 81。没有 provider 重试或缺失 usage。

随后游戏预试进一步暴露了约定层问题：把自由文字验收直接赋给旧的 `completion_criteria`，会被旧匹配器默认归入 Delivery，并要求名称匹配的交付证据。音效、碰撞、冷却等行为条件持续为 Unknown，代码已通过 23 项外置逻辑检查，部分子代理却反复自检。根因是语义复核与机器证据混用，不是增加并发导致失败。

因此没有放宽旧验证器的成功判据，而是让新 assignment 层保留语义清单并显式返回待复核状态；原有显式运行时条件保持不变。新增回归用“存在但未实现行为的模块”确认：文件交付可以完成，行为清单绝不因此被认证通过。

预试数据原样留在 `live/`：4 并发 227.139 秒完成、23/23；8 并发在 389.725 秒因上述循环被主动取消，4 个子执行 Completed、1 个 Partial、3 个取消，父任务取消。87 个受管进程全部终态，8 份 inbox 中 5 份已交付，其余在取消后保留。此组中止，没有继续第三、第四轮，也不混入修复后四样本统计。

预试首个游戏经真实 Ego 检查为 15/15。验收脚本首次因两个合法可见 Resume 按钮而定位不唯一，保留 11 通过/1 执行失败的记录；观察 DOM 后改为选定明确的可见按钮，原游戏未修改。桌面、窄屏和自然死亡截图已检查。

上述两项修正都完成后的最终构建再跑同一 CLI 预检，为 **16.029 秒**，仍是 8 会话、9 次成功执行、9 份空工具目录、9/9 inbox、零受管进程、一次无工具终答，正确返回 204 和 81。前后预检各只有一次，耗时不用于证明性能提升。

## 评测方法

完整游戏使用同一冻结 SDK driver、同一 v2 合同和外置 23 项行为验证器，顺序为 **4 / 8 / 8 / 4**。每轮都生成完整的八模块 ORBIT BREAKER 游戏，父代理负责整合，子代理各自实现所属文件。模型使用已有 `golutra / grok-4.7`、显式 low；工作区与状态隔离，不改全局配置。所有首次样本及模型自行纠错都保留，不挑选重试中的最好成绩。

生成计时包含父子模型、工具、纠错、运行时验证及正常回收；真实浏览器验收另行计时、不混入生成成绩。验收用 Ego 官方 SDK 的真实键鼠操作，游戏状态接口仅供观察，不能改状态制造得分。人工截图检查与自动断言分开记录。

每个并发配置只有两个样本；中位数和范围只描述这次探索，不推断稳定 P95 或最优并发。v2 合同增加了静音文字/aria、Resume 和窄屏要求，因此不能与旧 v1 的 141.211 秒直接作因果提速比较。token 是已记录用量，不等于费用。

原始证据：`/tmp/golutra-delivery-refactor.YOYthy/`。最终四轮放在 `live-final/`，保存每轮提示、元数据、二进制、日志、SQLite、原始游戏、逻辑验证及浏览器验收；`live/` 为保留的预试。临时目录可能被系统清理；最终机器摘要另存仓库。

第三轮的 129.436 秒并非调度器排队：父代理先读文件到约 16.6 秒，生成八条派发的模型响应耗约 84.3 秒，随后把 assignment 路径写成绝对路径，八个调用按既有相对路径规则被拒绝；再经过约 28 秒纠正后才入场。未放宽路径边界，失败调用也计入耗时。其他轮次仍有文件读取、shell 调用或重叠编辑错误，说明模型遵循与生成质量仍会影响收益。

成功工具中已记录的资源等待均为 0ms，仅覆盖表中这些事件；不代表所有未观测阶段都没有等待。本组游戏没有可用于估计通用后台工具排队耗时的样本，相关分布保持空值。后台结果确认发生在本来就进行的模型/工具边界，最大 61.272 秒延迟不是额外模型轮询的证据。被动附带交付减少重复收尾，但不承诺中断正在生成的响应立即注入结果。

### 界面缺陷及独立修复

真实键鼠验收包括移动、射击、实际击杀与得分、暂停冻结、静音文字和 aria 状态、继续、自然死亡、重开及页面异常观察。截图另查桌面标题、420×840 标题、窄屏暂停和结束界面。

第二份游戏的 HUD 在窄屏折成两行，高约 71px，而菜单仍使用固定 46px 顶部内边距，导致静音按钮遮住标题及 Paused 字样。自动检查只确认按钮在视口内，所以 15/15 并不能证明没有遮挡；人工验收明确记为失败。

在 `live-final/repairs/run-2-c8/` 创建独立副本，仅修改窄屏 CSS：HUD 和菜单分别进入 grid 的自动高度行与剩余空间行，取消固定偏移。副本重新通过 23/23 逻辑、15/15 真实浏览器行为检查及四个状态的截图检查；420×840 标题顶部为 86px，已位于 HUD 底部 71px 以下。原始样本、分数、耗时和文件不变，人工修复不计入 Agent 生成成绩。

评测汇总脚本已将自动操作与人工视觉记录分开；缺少人工记录时保持 null，不能计为综合通过。原始截图和修复截图分别保存，避免以后再次把逻辑成功当作界面成功。
