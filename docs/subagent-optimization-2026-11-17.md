# 子代理实测问题的优化与验证

日期：2026-11-17，Asia/Shanghai。承接 [游戏并行/串行实测](subagent-game-benchmark-2026-11-17.md)，本轮实现运行时修复、配置入口统一、派发指引和游戏界面修复。原始计时产物保持不变；所有修复游戏都是另外的副本。

八子代理游戏候选实测为 **141.211 秒、峰值并发 8、8/8 子执行完成、23/23 功能检查通过**。原并行样本为 177.589 秒，本次观测耗时降低 20.48%；首派发从 100.034 秒提前到 33.372 秒。每个版本只有一次完整游戏样本，不能据此宣称稳定提速。已记录总 token 从 610,818 增至 757,512，增加 24.02%，没有证明省 token 或费用下降。

## 实现范围

| 问题 | 实现后的行为 |
| --- | --- |
| 给子任务引用“no tools”会把父任务工具也关掉 | 移除任意目标文本的子串禁工具判定。工具面由明确的 profile/contract 控制；`AgentToolProfile::None` 仍为空工具集，模型仍须遵守自然语言约束 |
| 委派与大段整合文件同一响应生成，延迟所有子任务 | 工具描述和通用执行指引要求先发简短的独立派发响应，拿到句柄后继续主代理的独立工作；不提前执行未完成响应中的工具 |
| 完整读过子结果后，迟到的后台入箱又引发模型总结 | 记录实际 provider request 中的完整终态 findings，按 child session + execution task 确认迟到交付；基于已持久化请求确认消费，随后重新检查输入、取消和未完成工作 |
| CLI 项目配置写 low，实际仍沿用 provider high | exec 按命令行 → 项目 → 全局 → provider 默认解析 model/profile/effort；新增对应 flags 和 Rust per-turn facade。只改 effort 保留宿主 token/window/thinking 配置，不改用户保存的设置 |
| 菜单重影、窄屏遮挡、静音及暂停按钮反馈错误 | 修复副本由 DOM 负责菜单/HUD，菜单适应视口，明确静音文字和 aria 状态，暂停页显示 Resume；在真实 Ego 中复核 |

后台去重没有把所有终态都当作已读。正文缺失、截断、续页、上下文压缩丢失、同一子会话的新 execution 都继续交付；仅有状态句柄不够。混合交付保留未读项，用户输入和取消的优先级不变。结果仍静默入箱，没有新增用户通知。

运行入口与使用约定见 [runtime entrypoints](runtime-entrypoints.md) 和 [subagents](subagents.md)。`verify_on_change` 仍是 TUI 控制，exec 使用显式验证参数。没有统一改成 low，也没有修改上游重试或声称解决服务器 504。

合同、外置验证器和用户提示与原并行样本逐字相同，哈希一致；模型为既有 `golutra / grok-4.7`，通过 SDK 显式指定 low，父子 `TaskCreated` 均核对为 low。测试状态互相隔离，未改全局 provider 设置。顺序执行且每版 N=1，没有随机化、没有重跑挑最好值；第一候选后半段与下一候选本地编译重叠，不能拿它的总耗时作严格因果比较。

第一候选只改工具描述，模型仍一次生成八个派发和四个整合写入，响应耗时 86.821 秒。该样本不删除，也不描述为派发优化成功。加入通用执行指引后，派发响应只包含八个委派；四个整合写入在下一响应完成，期间子执行已经运行。派发响应耗时 30.148 秒，随后整合响应 17.761 秒。

最后八个子执行耗时 P50 为 62.254 秒，P90/P95/max 为 84.136 秒，采用 nearest-rank。它们是不同模块的耗时，不是同一任务反复执行的延迟分布。端到端 N=1 的分位数没有额外统计意义。

第一候选的九次工具错误包括五次缺失绝对路径前导 `/` 和四次自测/整合检查错误；加强指引样本保留两次读路径错误和三次 shell 检查错误。父子最终完成并通过同一外置验证器。没有通过忽略失败断言、修改验证器或篡改合同取得通过。

### 已观察与未观察结果

第一候选最终请求已经包含八份完整子结果：一次最终无工具响应后确认全部八条 inbox，**没有额外模型总结**，28 个受管进程均终态。

加强指引样本的批量 wait 在预算投影后只保留了七个已完成子的状态，之后单独 wait 完整读取最后一个子。运行时仅直接确认这一份；另外七份正文仍补交给模型，模型又读取一次后台结果后收尾。共两次确认事件、8/8 durable delivered，31 个受管进程均终态。这是必要的未读结果交付，不能为了消除最后一次续跑而丢弃正文，也不能把最终版本说成“永远只总结一次”。

### CLI 和最终源码

真实 CLI 预检 `cli-probe` 只在项目 runtime.json 设置 low，不传 effort flag。父、子实际均为 low，子代理在“no tools 仅约束子任务”的提示下返回 323，整体 7.100 秒，无工具错误或重试。配置优先级、显式 default 清除以及保留宿主 generation 字段另有隔离进程测试。

完整游戏的 141.211 秒来自保留的加强指引二进制。之后全量回归发现新增系统指引挤占小上下文预算，于是保留同一派发段落，压缩其他重复措辞：最终系统指引 1,895 字符，短于原来的 1,940 字符。未放大生产预算，也未放宽原有测试断言。该措辞压缩后的二进制另做真实八子代理 CLI 验收，和完整游戏计时分开记录，不冒称已经在完全相同最终二进制上再跑一次完整游戏。

最终源码 CLI 验收 `cli-final-probe` 为 **10.679 秒、8/8 子执行完成、峰值并发 8、正确返回平方和 204**。父子实际都使用项目 low，八条 inbox 全部持久确认，父代理仅一次最终无工具响应，无额外总结、无工具错误或 provider 重试。此处一名子代理仍额外调用了一次 shell，违反了测试提示中的自然语言“no tools”；该进程已终止。这也说明自然语言约束不是工具权限边界，需要硬性禁工具的调用方应使用显式 profile，不能恢复任意引文触发的全局禁工具逻辑。

## 回归中的失败与修正

首轮四 crate 测试中工具描述超过 256 字符；第一次压缩又漏掉原有“omit it on spawn”约定，LLM 测试失败。最终描述为 250 字符，同时保留返回句柄、并行派发、批量 wait、60 秒上限和禁止子代理再委派。

随后全工作区测试跑完，只有 client 三项失败：两个取消测试因新系统指引使保护前缀超过 4096 而未启动子工具，一个可选记忆预算测试失去余量。压缩重复措辞后，三个原测试均恢复通过；没有将它们归为偶发超时或修改上限。首次和中间失败日志完整保留。

新确定性回归覆盖英文/中文/README 引文不会关闭父工具，显式 None 仍为空；迟到的完整单个/批量子结果不增加模型请求，截断结果和新 execution 仍需请求；确认消费引用已经捕获的请求。CLI 进程回归通过真实 App Server 核对 flags、项目/全局优先级、默认清除、配置不被改写，排队输入不能暗中切换活动任务 effort。

最终源码按 test target 合并：**2,366 通过、0 失败、11 显式忽略，59 个 target**（含无测试的 binary/example target）。client 全目标 478 项通过，其他 workspace 全目标 1,888 项通过；没有重复相加之前运行或子进程的嵌套测试摘要。严格全工作区 Clippy（`-D warnings`）、构建、fmt 和 diff 空白检查通过。环境依赖的显式忽略不计入通过数。
