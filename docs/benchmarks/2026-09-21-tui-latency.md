# TUI 输入与流式显示优化验收

环境：2026-09-21，macOS ARM64，120 列 × 32 行真实 PTY。修复前基线为 `991839d` 的 debug 构建，修复后为同一工作区的 debug 构建。没有把 release 相对 debug 的编译优化算作本次收益。

本报告保留第一轮修复的结果；随后对照 Codex/pi 的解析和写入优化见 [第二轮对比与实施](2026-09-21-tui-codex-pi-comparison.md)。

## 修改范围

- 原生历史未变化时跳过归档工作；已提交完整条目不再重复排版。
- 历史投影按 revision 和命令锚点复用，活动区高度与正文共享布局。
- Markdown 仍完整解析以处理后置链接定义、表格和列表变化；已相同的语义块复用排版，代码块只重排最后一行和新增行。修订或宽度变化重新计算，正文不截断。
- 输入框同一文本/光标/宽度复用布局；编辑、撤销、重做、清空与替换使缓存失效。
- 首次 `@` 扫描放到可取消的后台线程；用当前草稿生成候选，工作区变化时丢弃旧结果。
- 交互维护最多处理 32 个事件后返回主循环，保留队列顺序，不丢弃内容。
- 入队和回放只约束新载入的 payload，去掉每条新事件到来时对整个窗口的重复序列化；原有单条与总量预算继续生效。

## 流式结果

本地 Responses SSE 服务分别向真实程序发送相同正文，排除真实模型和外网因素。每场景 400 个编号片段，均匀场景目标每 25ms 一段；突发场景每 200ms 同时发送 8 段。解析终端控制序列，在同步更新结束后观察编号首次出现在屏幕的时间。

| 场景 | 后 100 段延迟中位数，修复前 → 后 | 全程 P95，修复前 → 后 |
| --- | ---: | ---: |
| 中文分段正文 | 57.79 → 6.26 ms | 73.55 → 10.59 ms |
| 400 行代码围栏 | 66.47 → 12.64 ms | 79.29 → 13.59 ms |
| 无换行中文长段落 | 58.44 → 22.41 ms | 69.90 → 25.25 ms |
| 突发中文正文 | 46.68 → 9.04 ms | 49.52 → 22.08 ms |

四场景都观察到 400/400 个编号。修复后数据来自移除临时计时代码后的最终构建。以上每场景各一次，不代表跨机器统计结论；时间包含本地 runtime、TUI、PTY 传输与 Python 屏幕解析，不包含真实终端 GPU 和输入法候选窗口。

额外在代码流进行到第 200 段后连续输入 30 个 ASCII 字符：输入上屏中位数 13.24ms、P95 18.70ms、最大 19.17ms；400 个输出编号仍全部观察到，草稿未提交。该额外场景在排版优化后、事件重复序列化修复前测得，未混入上表。

先前同机 Codex 0.155.1 的代码流后段中位数约 12.96ms。本轮修复明显缩小了 debug 构建的长度效应，但不能由这些样本声称普遍超过 Codex。本地参考源码为 `fc269b66`，不假定与已安装二进制完全一致。

## 输入结果

每场景 30 个 ASCII 字符，观察到当前字符后等待 35ms 再输入下一个，均为 debug 构建。下表在排版优化后、事件重复序列化修复前测得；后者不修改空闲输入框路径。

| 场景 | 中位数，修复前 → 后 |
| --- | ---: |
| 空会话短输入 | 2.71 → 2.55 ms |
| 1,000 字符草稿 | 4.18 → 2.80 ms |
| 8,000 字符草稿 | 12.47 → 4.14 ms |
| 64,000 字符草稿 | 75.88 → 14.49 ms |
| 首次 `@` 出现在屏幕 | 62.60 → 2.77 ms |

`@` 的数据只衡量输入回显，不把后台扫描完成时间伪装为 2.77ms。草稿仍完整编辑，没有引入长粘贴占位符改变比较负载。

第一阶段排版优化后，40 轮历史键入中位数由 8.87ms 降到 2.65ms，但没有等待任务收尾的夹具仍捕获到 654ms 单样本停顿（原基线 737ms）。显式确认 `/status` Completed 后再测，最大值只有 3.01ms，因此继续定位切换阶段而没有删除离群值。

临时阶段计时将停顿定位到维护循环中的事件批次，复测捕获到 714ms；绘制不是该停顿的主要耗时。代码在入队/回放约束 payload 后，还会在每次 trim 时重复序列化整个已保留窗口。去掉这层重复工作后，用相同的不等待收尾夹具复测：40 轮键入中位数 2.44ms、P95 2.71ms、最大 2.89ms；未再捕获超过 40ms 的事件批次。临时计时代码随后移除，不新增产品环境变量或日志。

移除临时计时后，再用最终 debug 程序复测同一夹具：40 轮历史输入中位数 2.48ms、P95 2.68ms、最大 3.47ms；0 轮和 10 轮中位数分别为 2.39ms、2.28ms。此次未再观察到基线中的收尾停顿，结果保存在 `final-history-results.json`。

## 正确性检查与范围

- TUI 包完整测试：450 项通过（19 lib、396 TUI、28 PTY、7 Driver），1 项真实上游 smoke 默认忽略。
- 新增逐字符 Markdown 对照，覆盖中文、组合字符、emoji、代码围栏闭合、窄窗口、表格、列表、引用链接、缩放和最终正文修订；缓存输出与完整解析的文字及样式一致。
- 新增输入缓存编辑/光标/撤销回归、后台 mention 当前草稿/旧工作区回归，以及事件积压跨批次有序处理回归。
- 新增入队/回放 payload 裁剪回归，验证正文完整、元数据受限，并且后续事件和预算检查不会反复改写原始大小信息。
- 原有真实 PTY 覆盖 resume、`/status`、长块结束、缩放、全屏进出、草稿和原生滚动历史。
- Clippy 全目标零警告；格式与 diff 检查通过。

首次完整单测中四项 localhost HTTP 夹具受到宿主代理影响而出现 502/OAuth 请求错误；给测试进程设置 `NO_PROXY=127.0.0.1,localhost` 后全组通过，未修改用户代理配置。逐字对照还发现过闭合代码围栏时多出空行的问题，修正后全组通过。

这一轮没有实机测试 Windows/Linux，也没有用新 release 构建重复性能测量。超长单段仍有完整解析和换行成本，缓存解决重复工作，不承诺任意正文长度下恒定耗时。网络批量到达时仍按收到的内容刷新，没有固定逐字等待。

本机诊断脚本、ANSI 记录及时间线保存在 `/tmp/golutra-input-diagnosis.iaJxiC/`：`streaming.py`、`measure.py`、`history.py`；基线 `stream-results.json`；最终流式结果 `final-stream-results.json`；阶段结果 `after-stream-results.json`、`after-input-results.json`、`after-history-results.json`、`after-typing-stream-results.json`；事件修复复测 `after-event-fix-history-results.json`；定位记录 `transition-timing.log`、`transition-phases.log`、`transition-fixed.log`。均使用隔离配置与假密钥，未请求真实模型。临时目录可能被系统清理，本报告保留测量方法和汇总结果。
