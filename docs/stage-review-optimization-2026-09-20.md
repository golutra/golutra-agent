# 阶段收尾与模型往返优化

日期：2026-09-20。保持 0.3.1；不提交、推送或发布。保留上一轮默认无限长任务改造。

## 假设与实现

上一轮完整四阶段任务中，一次 Golutra 执行在后台探针退出后才修复零计数遗漏，违反阶段顺序。轨迹没有压缩、断网或工具乱序；不能据此归因于传输层。

本轮候选只调整通用系统提示的相关语义：

- 已知独立读取可批处理；未知路径先发现，再根据结果读取，避免把有依赖的工作误放进同一批。
- 成功写入不必仅为确认落盘而重读；检查逻辑、边界和原始要求时允许必要复查。
- 关闭阶段、释放依赖资源之前完成相关实现与检查；普通等待不冻结文件。最终交付核对原始要求和后续修改，测试通过不代表全部业务要求已满足。

不增加默认模型裁判、每轮额外检查请求、自然语言硬性门禁或监督服务。默认任务总预算、纠偏轮数继续不限；权限、取消、显式预算和工具容量边界保持原有行为。

## 确定性验证

## 实跑暴露的代码缺口

第一轮金额重构的基线先成功运行 unittest，再成功运行 `py_compile`。后一项只改写 `__pycache__/*.pyc`，却使前一项测试被判过期。之前的缓存豁免只覆盖正式测试，未覆盖成功的编译诊断。模型之后修改命令、删除缓存并重复测试，发生六轮纠偏，总计 25 次模型请求、约 161.6 秒；产物最终通过，不能把这个样本算作失败。

该轨迹说明提示优化可能通过减少无用操作绕开缺口，但不能代替运行时修复。旧判定已由规则回归和真实 unittest→字节码生成流程分别复现失败，随后才修复。

根因修复不新增 `py_compile` 命令特判，也不把整个缓存目录视为无关变化：

- 工具层利用已经存在的完整前后快照，识别有标准源文件映射的派生产物。当前只支持 PEP 3147/488 源码关联字节码：源文件须在两侧存在，有完整摘要且内容、大小、权限不变；孤立字节码、未知格式、源文件改动或扫描不完整不能获得标记。
- 进程报告保留原始 changed_files、before/after images 和审计证据，额外提供内部 `workspace_only_derived_changes` 事实。并发重叠使扫描不完整时该事实为 false；该字段不增加模型可见工具结果的正文。
- 独立 `validation_freshness` 模块消费工具事实，移除运行时按“测试命令 + .pyc 路径”豁免的规则。只有成功内置进程的完整、已证明派生变动不使源码验证过期；直接编辑、外部工具、失败以及未知副作用不豁免。

这里的源文件映射用于避免正常编程流程的冗余复验，不是对同权限恶意进程篡改字节码的完整性防护。没有推断任意构建目录或所有语言的依赖图；未知产物仍保守处理。显式路径、内容、外部业务验收继续独立执行，不能用该标记覆盖失败。

新增真实进程回归包含不同字节码生成入口以及后续真实源码改动；扫描层覆盖标准缓存标签、优化标签、缺源、缺摘要、不完整扫描和混合源码变化。共享工具/运行时规则与 provider 协议无关。

最终四阶段对照的第三轮旧版还出现了另一入口：`compileall`/CLI 导入生成字节码后使 unittest 过期，随后缓存删除、重新生成和不同命令身份引出五次纠偏。它进一步说明不能只给最初见到的 `py_compile` 补命令特例；该轨迹保留在最终对照原始记录中，未用于改写基准提示或降低验收标准。

## 完整任务中的剩余证据边界

最终版第二轮完成全部四阶段，但出现两次复验纠偏。轨迹显示模型在成功测试之后修改 `ledger.py`，随后用 `unittest && py_compile` 及包含多项检查的脚本复验。源码变动确实使旧测试过期；当前复合命令证据无法替代原先独立测试的身份，因此单独重跑原命令后才解除。该轮字节码创建/删除已正确获得派生标记，没有让新验证再次过期。这不是原缓存缺陷复发。

该限制需要解决的是复合 shell 内部执行证据及验证身份，不应以新增编译命令白名单、任意成功命令替代测试或忽略真实源码变动来绕过。本轮不弱化此边界，也不承诺零纠偏。该样本还包含一次 60.6 秒模型请求，首个业务输出等待约 33 秒、输出 5564 token；模型生成、等待及额外往返共同构成耗时，不能把全部时间都称为网络故障。
