# 后台终端

`shell` 与 `shell_session` 共用运行时的 `ProcessSupervisor`。命令首次返回、操作系统进程退出、工作区扫描完成是三个独立状态；一次工具调用返回成功，不代表后台程序或外部业务已经完成。

## 启动与接续

普通 `shell` 默认等待最多 10 秒，然后返回已完成结果或可继续使用的 `process_id`。`background=true` 默认立即交还控制权。两种方式都可以通过 `yield_time_ms` 指定首次等待时间，最多 30 秒。

`timeout_ms` 是进程的硬生命周期，默认一小时，最大 24 小时。它与首次等待时间、后续读取的 `wait_ms` 分开计算。读取等待到期不会终止进程；显式终止、所属任务取消和宿主关闭会清理受管进程。

启动示例：

```json
{"command":"cargo test --locked","background":true}
```

随后使用返回的句柄：

```json
{"action":"wait","process_id":"<返回的 process_id>","wait_ms":1000}
```

`shell_session` 支持 `wait`、`read`、`write`、`terminate`、`list`。`wait` 等待执行或新输出；`read` 立即读取已有输出，即使传入等待参数也不等待进程完成。除 `list` 外都需要 `process_id`；不必重复提供操作系统 PID，提供 `authoritative_pid` 时仍会校验。句柄只允许在所属会话内访问。不同进程的 wait/read 可以并行，同一进程的交互保持顺序。

默认采用管道。需要交互式程序时可在启动时设置 `tty=true`，再用 `write` 发送 `input`。Unix PTY 使用独立会话与控制终端，当前尺寸固定为 120 × 24，不跟随 TUI 窗口缩放；其他平台不支持 PTY。直接解析的 heredoc 输入使用管道模式，PTY 下可显式调用 `bash -lc` 执行 heredoc。

## 输出读取

读取默认沿用上次交付的游标；显式 `cursor` 支持重读。预览默认 12288 字节，通常不需要指定 `max_output_bytes`。该参数是软预算：最小 256，更大的请求由运行时封顶为 12288，而不是拒绝命令。最终模型结果通常最多 4096 token（按 4 字节/token 的预算估算），上下文紧张时进一步收缩。UTF-8 字符不会被正常分页或分片读取拆坏。返回值区分：

| 字段 | 含义 |
| --- | --- |
| `output_start_cursor` | 本次读取起点 |
| `output_cursor` | 本页交付终点，用于后续读取 |
| `output_end_cursor` | 进程目前产生的输出终点 |
| `output_has_more` | 已产生但尚未交付的输出是否还有剩余 |
| `output_lost` | 起点是否早于当前保留窗口 |
| `process_state` / `exit_code` | 进程状态与退出码 |

`output_has_more=true` 只表示存在未读内容，不表示进程仍在运行。终态以 `process_state` / `terminal` / `exit_code` 为准。只有任务需要更多内容、完整输出或验证证据时才继续读取；已结束进程的 `next_action` 为可选 `read`，而不是执行等待。模型输出预算进一步截断内容时，结果提供明确的重读游标和较小预算；需要续读时使用该游标，不能重新执行原命令来获取输出。失败退出码和真实失败状态不会因输出截断而变成成功。

单进程最多保留 2 MiB 输出；更早内容被回收时明确标记丢失。结束进程的缓存最多 32 个、合计 32 MiB，空闲保留时间最多 15 分钟，在缓存维护时清理。最多允许 64 个活动进程。`list` 默认每页 4 项，提供 `offset`、`limit`、`has_more`、`next_offset`，单页最多 64 项。列表中的 `next_action` 从已交付位置接续，即使进程已退出，也不会跳过未读输出。旧 `process_*` 工具接口继续保留兼容。

## 并发与工作区事实

同一轮模型返回的连续后台启动可以组成并行批次；不同进程的连续 `wait` 可以并行。同一进程的交互由独立互斥锁串行化，写入、终止及普通可变前台命令保留调度顺序边界。跨模型轮次的调用不会被重新排列。

运行时先执行现有权限、任务契约和治理检查，再调度命令。后台启动批次复用一次工作区基线采集。工具结果附带实际 `execution_mode` 和 `dispatch_batch_size`，模型可以据此说明调用是串行还是并行，不能仅凭 `background=true` 推断。

进程退出立即发布状态，工作区扫描随后完成，期间 `workspace_scan_pending=true`。多个可写进程在同一工作区重叠执行时，结果会标记 `workspace_overlap`，不将共享工作区差异确认为某个单独命令的修改。扫描属于工作区观测，不替代业务完成判断。

只读快路径支持语法树可证明安全的简单命令列表和管道，不改变权限审批。复杂脚本、动态展开和可能写入的命令使用有界采样：前后每次扫描预算为 250 毫秒，单文件最多哈希 8 MiB、总计 32 MiB，保留的恢复内容最多 2 MiB。预算在遍历及读取分块之间检查，操作系统 I/O 和调度可能带来额外耗时。超出预算的状态保持未知；未采样文件不会被记成新增或删除。定向文件编辑继续保存其明确目标的 before-image，不受此采样预算影响。

## 事件与 TUI

运行时独立监听输出和进程状态，通过 `ProcessUpdated` 发布并持久化快照，不要求模型发起轮询才能发现完成。输出更新节流为 250 毫秒，每次读取最多 4 KiB 尾部正文，经过脱敏和终端控制字符过滤后形成事件摘要。事件用于界面和恢复投影，不作为普通模型上下文消息持续回灌。进程终态优先于晚到的启动返回快照，恢复分析和界面不会把已结束的进程重新标记为运行中。

TUI 显示命令、运行状态和进程耗时。同一终端的连续等待在尚未归档的尾部合并；不会越过用户消息、助手消息或错误。启动记录已进入原生终端历史时，完成事件追加一次完成提示，详情继续更新，不覆盖既有历史。展开工具详情仍使用现有独立全屏页面，主聊天保留原生终端滚动与复制。

普通已完成命令显示 `ran`，后到的进程终态事件不再改写为后台完成；显式续读显示 `Read terminal output`。真正后台运行的命令保留运行/完成提示。

流式回答以原始 Markdown 文本判断是否发生真实修订。表格补齐、换行和终端宽度变化不再被误判成整条回答被替换。

## 生命周期边界

受管进程依赖当前运行时宿主。宿主正常关闭会取消进程、等待退出与工作区扫描，并保存最终快照。关闭等待直接持有进程对象，避免缓存回收导致清理过程丢失句柄。

持久事件保留已经观测到的状态，不会让重启后的宿主重新接管任意旧 PID，也不会自动重提可能产生副作用的命令。进程退出码只表示程序执行结果；外部 CLI 的业务状态、异步请求是否完成，仍需按该 CLI 协议判断。
