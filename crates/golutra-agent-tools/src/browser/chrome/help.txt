Chrome extension backend (protocol 1).
The extension connects to the local Agent automatically. This does not authorize existing tabs. Automatic task creation is enabled by default on installation. Unless the user has stopped it, browser_status reports can_open_task:true; use browser_run action:open with an http/https url to create and bind a NEW task tab in this Chrome Profile. Existing login state is reused. Never adopt existing tabs automatically. open requires no active task; finish first before opening another. A stopped/disconnected task is not resumed by reconnecting. User Stop disables automatic tasks until explicitly enabled again. Status never creates tabs.
browser_launch opens/focuses the user's installed Chrome with its existing Profile; it does not navigate, choose an account, install the extension or grant access. Check browser_status afterward. Never treat launch_requested as connected, copy login tokens, or use launch to bypass Stop. CLI/TUI setup: /connect launch-chrome, then /connect install-chrome if needed. After loading the extension, new task tabs need no setup clicks.
Automatic selection prefers installed Ego, then Chrome. Explicit configuration takes priority. If neither is installed, ask for consent before installing Ego with /connect install-ego or golutra-agent browser install-ego --yes after consent. Ego uses its native SDK; keep OpenCLI disabled in Ego to avoid reconnect conflicts with Chrome. Never switch after an error, bypass user Stop or replay an uncertain action.
Only user-authorized existing tabs or newly created automatic task tabs are accessible. The first browser_run binds the selected tab to this workspace/session; other sessions are refused until finish. User-owned tabs are never closed. Use Ego for isolated task spaces or Node scripts.
browser_status observes connection/binding. browser_handoff releases debugging; stop until user confirms. To resume after confirmation pass resume_after_user:true. If the extension Stop button was used, the user must explicitly reauthorize the same tab using its popup, or choose “恢复自动运行” to start a new task page. Never switch profiles or adopt existing tabs automatically. browser_finish releases the session without closing the page; if can_open_task is true, open can start the next task without another popup approval.
browser_run supports one action:
- open: url, http/https only; create a new task tab when automatic tasks are enabled, without separate per-page approval. Verify loading with snapshot. Do not use navigate before a target is bound. Existing authorized tabs still use navigate.
- snapshot: visible DOM text and interactive elements with CSS selectors (including iframe content when accessible); no mutation.
- frames: enumerate frame_id and URL for the authorized tab, including cross-site child processes (Chrome 125+). For cross-origin frames pass the observed frame_id to snapshot/fill/click/evaluate. Re-observe if a frame is replaced. Frame expressions run in an isolated DOM world, not the page's application JS globals. Frame click uses DOM click (trusted:false); sites requiring trusted pointer events may need user handoff or Ego. Other actions do not accept frame_id.
- navigate: url, http/https only. Then snapshot to check loaded content.
- click: selector (CSS, exactly one visible element). Handles DOM/shadow roots and frames. Verify result with snapshot.
- fill: selector and text; dispatches input/change events.
- press: key (Enter, Tab, Escape, Backspace, ArrowLeft, ArrowRight, ArrowUp, ArrowDown, or one printable character).
- scroll: x/y wheel deltas (CSS pixels), then snapshot.
- screenshot: real PNG image returned to model.
- evaluate: expression executed in the selected page, not Node; JSON result only, bounded 10s. No local filesystem or shell access. Use for application state/extraction when normal actions do not suffice.
- upload: selector for input[type=file], files absolute paths. Runs only in unrestricted mode.
- download: url on the selected page's current origin; uses Chrome download manager/cookies, saves in the user's normal Downloads directory. Returns download ID/path once completed. No automatic retry on timeout.
browser_status lists direct HTTP/HTTPS popups. To continue in a popup, call browser_handoff and ask the user to activate it and click “在此关联页面继续当前任务” in the extension. This preserves the current session/binding. The same flow can return to a previously authorized page (last 32). Unrelated tabs are refused; there is no automatic adoption. “使用当前标签页” on an unrelated tab starts a new binding.
chrome:// pages, extension pages, and file:// are not supported. Native file pickers, OS permission dialogs and CAPTCHA require user handoff; use upload for file inputs. Disabled/read-only fields and covered click targets are refused. Screenshots/DOM may include sensitive page data: use only pages authorized for the task. After a side-effect timeout/cancellation, inspect before retrying; dispatched operations may finish late.
